# 需求记录（2026-11-27）

## R1 删除「日志配置」指令

**现状**（`cmds.ini`）：

```ini
[cmd.stlogcfg]
desc = 日志配置：打开工程模式主页（日志设置入口）
group = SynTestUtil
usage = stlogcfg
run = shell am start -n com.android.engmode/com.android.engmode.MainActivity
```

**要求**：删除该指令（入口已由 R3 的「打开日志设置」取代）。

**影响**

- 指令页「配置入口」分组少一张卡
- 若有人用 `stlogcfg` 命令名，删除后不可用（建议保留别名或确认无外部调用）
- `cmds.ini` 与 `dist/cmds.ini` 两处都要删（打包用它）

## R2 「下线配置」指令无效

**现状**：

```ini
[cmd.stoffline]
desc = 下线配置：工程模式-离线配置页（SynTestUtil xxpz）
group = SynTestUtil
usage = stoffline
run = shell am start -n com.android.engmode/.ui.OfflineConfigActivity
```

**现象**：点击后无法打开目标页（Activity 路径不存在）。

**用户提供的正确信息**

```
包名      com.android.engmode
Activity  com.android.engmode/.MainActivity
```

**建议改为**

```ini
run = shell am start -n com.android.engmode/.MainActivity
```

**待确认**：`.MainActivity` 是工程模式主页，还是就是“下线配置”页？
若是主页，需要用户提供真正的离线配置 Activity（原 `.ui.OfflineConfigActivity` 已失效）。

## R3 新增「打开日志设置」指令

**要求**：新增一条指令，直接打开设备上的日志设置页。

**用户提供的信息**

```
包名  com.gxa.car.systemlog
Activity  未提供
```

**建议写法（二选一，需确认）**

```ini
# 方案 A：已知 Activity
[cmd.stlogset]
desc = 日志设置：打开车机日志设置页
group = SynTestUtil
usage = stlogset
run = shell am start -n com.gxa.car.systemlog/<Activity>

# 方案 B：只知道包名，用 monkey 启动入口 Activity
[cmd.stlogset]
desc = 日志设置：打开车机日志设置页
group = SynTestUtil
usage = stlogset
run = shell monkey -p com.gxa.car.systemlog -c android.intent.category.LAUNCHER 1
```

**推荐方案 B**：只要包名即可工作，不依赖具体 Activity 名；
缺点是输出是 monkey 日志，不是干净的 am 结果。

**待确认**

1. 该应用的入口 Activity 名称（有的话用方案 A，输出更干净）
2. 指令名用 `stlogset` 还是别的（避免与 R1 删除的 `stlogcfg` 混淆）
3. 归到「配置入口」分组还是「信息查询」
