# 参考研究：Edge 的主题/强调色设置，以及同类实现能给我们的启发

> 起因：用户第 6 条需求 —— 把 Edge 的外观设置当参照，看看我们这套「主题 × 强调色」有没有可借鉴或可优化的地方。
> 结论先说：**我们的方向是对的，缺的是三样东西**：分组与命名、选择前的"预览"、以及"配色选择"之外的场景化入口（按设备/车型）。
> 本文最后给出 5 条优化建议，其中 1 条已在本轮落地，另外 4 条明确标了成本与风险，不做也能用。

---

## 一、Edge 是怎么做的（事实部分）

Edge 把外观拆成三个互相独立的维度，这个拆分方式本身值得学：

| 维度 | Edge 的做法 | 我们对应的实现 |
|---|---|---|
| 明暗模式 | Light / Dark / **System default**（跟随系统） | `data-theme` = light / dark / eye（护眼），另有 `auto` 跟随系统 |
| 强调色 | 一排色块，点一下**立即生效**，不需重启 | 16 色点，点即生效 |
| 完整主题 | Edge 商店主题会覆盖上面两者（并带新标签页壁纸） | 我们没有第三方主题，所以没有"覆盖优先级"问题 |

Edge 的强调色清单是这些（[AskVG 的实测列表](https://www.askvg.com/tip-customize-microsoft-edge-ui-and-theme-using-new-accent-color-feature/)）：
浅灰、深灰、深蓝、中蓝、浅粉、粉、薄荷、蓝绿、灰蓝、紫、红、黄、橙、绿。

三个关键点：

1. **每个颜色有 light / dark 两套派生值**。同一支"蓝"在浅色下更暗、深色下更亮，用户选的是"语义色"，不是某个 hex。→ 我们已经这么做了（48 条 `主题×色` 规则，全部过 WCAG）。
2. **中性色也是强调色**。浅灰 / 深灰在列表里和彩色平级 —— 说明"灰色系当强调色"不是我们发明的需求。→ 我们的石墨 + 三白正好对应，方向一致。
3. **即时预览**。点色块当场变，不重启、不确认。→ 我们也是。

Edge 的短板（也是我们容易照抄错的地方）：

- 色块**没有名字**，也没有"这色在浅色下会怎样"的说明。16 个圆点里 3 个近白点，用户只能靠猜。
- 明暗模式是 4 个纯文字按钮（Light / Dark / System default / …），**没有缩略预览**，选之前不知道长什么样。
- 强调色是**全局单值**，不跟随窗口/配置文件。Edge 只有"每个 profile 一套"这种粗粒度。

## 二、GitHub 上同类实现的三个可复制做法

| 项目 | 做法 | 对我们的价值 |
|---|---|---|
| [leomiranda/react-color-picker](https://github.com/leomiranda/react-color-picker) | 不给自由取色，改为**每个基色自动生成 5 个和谐变体**（Primary/Secondary/…），保证"不会选出破坏设计系统的颜色" | 和我们的思路同源：16 色 × 3 主题 = 48 个**已校验**的值，用户不接触 hex。这条要守住，不要开放自定义取色 |
| [zenui-labs/zenui-color-picker](https://github.com/zenui-labs/zenui-color-picker) | preset 色板 + **最近使用历史** + 键盘/焦点可达 | 历史对我们是负收益（永远只用 1~2 个色），但**焦点可达**值得抄：我们已支持 `:focus-visible`，方向对 |
| [PaletteSnap](https://github.com/mdombrov-33/PaletteSnap) | 选完色给**真实 UI 组件预览**（按钮/卡片/文字），并实时显示 **WCAG 对比度徽章** | 最值得抄的一条：把"对比度 ≥4.5:1"从生成器里的断言，变成用户能看见的信任凭证 |

另外 [Flutter 的 appearance 屏实现](https://rohansurve.in/pro/screens/fintech-appearance) 里有两条细节，是"看起来专业"和"看起来业余"的分界线：

- 选中态用 **外圈 + 勾双信号**，并且**未选中时也画同宽的透明边框** —— 否则点来点去色块会跳动一像素。
- 主题选项用**缩略预览卡**（一张小卡片按当前明暗真实渲染），不是纯文字按钮。

> 这两条我们**已经满足**：`.accent-dot.sel` 用 `box-shadow` 画外圈（不占布局）、勾是 `::after`；色点本身有 1px 边框，选中不改宽度。

## 三、逐条对照：我们已对齐 vs 还差什么

| 能力 | Edge | 我们（A17 后） | 差距 |
|---|---|---|---|
| 明暗三态 + 跟随系统 | ✅ | ✅ light / dark / eye / auto | 无 |
| 强调色即时生效 | ✅ | ✅ | 无 |
| 每色有 light/dark 派生 | ✅ | ✅ 48 条规则，全 ≥3:1 / ≥4.5:1 | 无 |
| 中性色可选 | ✅ 浅灰/深灰 | ✅ 石墨 + 纯白/护眼白/玻璃白 | 无（且比 Edge 多两档暖/冷白） |
| 色块有名字 | ❌ | ✅ `title` + `aria-label`（纯白/护眼白/玻璃白…） | 我们更好 |
| 选中态不跳布局 | — | ✅ box-shadow 外圈 + 勾 | 无 |
| 色板**分组** | ❌ 混排 | ✅ **本轮新增**：彩色 13 个 + 「中性色」分隔标签 + 3 个白 | 已补 |
| 对比度可见 | ❌ | ⚠️ 只在生成器断言里，界面上看不见 | **建议 1** |
| 主题选择有预览 | ❌ 纯文字 | ❌ 纯文字分段按钮 | **建议 2** |
| 按设备/车型区分配色 | ⚠️ 只有 profile 粗粒度 | ❌ 全局一套 | **建议 3** |
| 自定义 hex | ⚠️ 部分版本有 | ❌ 故意不做 | **建议 5（不做）** |
| 历史/收藏 | ⚠️ 部分实现有 | ❌ | 不做 |

## 四、5 条优化建议（按性价比排序）

### 建议 1：色点 hover 显示对比度（成本 30 分钟，风险低）

现在 `title="纯白"`，改成 `title="纯白 · 对比度 4.6:1（AA）"`。
数值从 `_gen_accent.py` 的校验结果直接抄进生成器输出，避免手写漂移。

> 为什么值得：用户不敢选白色，本质上是不信任"白色还能看清字"。把数字给他看，比任何说明文字都有效。

### 建议 2：主题三选改缩略预览卡（成本 2~3 小时，风险中）

把「跟随系统 / 浅色 / 深色 / 护眼」四个文字按钮，换成 4 张 96px 高的迷你窗口缩略图：
标题栏 + 两条内容条，用对应主题的真实令牌渲染（`var(--surface)` / `var(--text)` / `var(--accent)`），选中的那张画 2px 强调色边框（宽度恒定，不跳）。

> 风险点：设置面板本来就窄（288px 弹层 / 抽屉），4 张卡要改成 2×2；字号变大时可能挤 —— 需要跟 `--fs` 五分组件一起验。
> 收益：明暗切换是"每天都会碰一次"的操作，这一步的直观度提升最明显。

### 建议 3：按设备记住强调色（成本半天，风险中）

我们的用户场景是**多台车机 / 多车型**（Max-8838-T75、A8R_8295、T09M_8295、AHT、V20…）。
可以让强调色跟着**当前连接的设备序列号**走：插上 A8R 是蓝，插上 T09M 是橙 —— 一眼就知道"现在测的是哪台"。

> 实现：`_prefs.accentByDevice = { serial: 'blue' }`，`prefsApply` 时按 `App.SERIAL` 取。
> 风险：设备切换时页面要重染一次色，`applyAccent` 是幂等的，成本很低；但要加"恢复全局默认"的出口，否则用户会困惑。

### 建议 4：把"主题"和"强调色"合成一个"外观"区（成本 1 小时，风险低）

现在设置抽屉里，显示选项、强调色、字体是三段并列。Edge 把它们收在一个 Appearance 页里，顺序是
**明暗 → 强调色 → 字体/密度**。我们照这个顺序排一遍，语义更顺（先大后小）。

### 建议 5：**不做**自定义取色（明确记录理由）

看起来是"功能缺失"，其实是**保护**：我们 48 条配色规则全部经过 WCAG 校验（对表面 ≥3:1、其上文字 ≥4.5:1）。
一旦开放 hex，用户选个 `#FFFF00` 配浅色背景，字就看不清了，而这会被记成"工具的 bug"。
Edge 自己也只在部分版本提供自定义取色，且明确提示"效果取决于明暗模式"。

> 如果以后真要放开，前提是：取色后**实时算对比度**，不达标就把 `--on-accent` 自动切成黑/白，并给一条警告。

## 五、本轮实际落地了什么

1. **色板加分组标签**（建议 0，成本 5 分钟）：13 个彩色之后插入一条分隔线 + 「中性色 · 浅色/护眼下会压成灰（白压到可读对比度必然是灰）」。
   落点：`ui.html` 的 `<!-- A15:DOTS -->` 块内 + `_v17.css` §7；断言在 `_check_accent_dom.py`（仍是 16 个可点色点）与 `_v17_checks.py`。
2. 其余 4 条写成建议，**没有动代码** —— 建议 2 和 3 会改设置面板结构与偏好 schema，应该单独一轮做，避免和这轮的"九条 + 两条追加"混在一个提交里。
