# 测试用例（Adb_Tool · 基线 A22 / 2026-11-16）

> 设计口径：**从需求出发，不从代码出发**。每条用例锚定一条"用户能感知的承诺"，
> 再落到可判定的预期。凡预期写成"应出现 X"的，必须能截图或读 DOM/日志为证；
> 凡预期写成"不应出现 X"的，必须说明观测方式（否则无法判定）。
>
> 编号规则：`<维度前缀>-<两位序号>`。执行方式标在"方式"列：
> - `gate` 已纳入 `verify_all.py`，跑门禁即覆盖
> - `auto` 可用 `377/_test_*.py`（headless Edge）自动化，本文件给出断言点
> - `cli` 走 `adb_log_export.exe --exec` / `-selftest`（无 UI，纯逻辑）
> - `dev` 必须真机 + 真窗，人工执行
> - `man` 只能人工判定（体感 / 视觉）

## 0. 环境前提（缺一项就要在报告里单列，不许静默跳过）

|---|---|---|

| 账号 | GitHub `liyiadbtool` 已授权本机 SSH | 与功能无关，仅影响拉代码 |
