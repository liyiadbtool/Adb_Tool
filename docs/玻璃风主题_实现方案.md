# 「玻璃风」落地评估（2026-11-16）

> 问题：想在现有配色体系里加一个"玻璃风"，怎么落地、UI 怎么实现、代价多大。
> 结论先说：**玻璃是"材质"不是"颜色"**，所以有三种落法，成本和风险差 3 倍以上。推荐方案 B。

---

## 一、先厘清三件事（这三种"玻璃风"完全不同）

| 方案 | 是什么 | 现有体系里对应什么 | 成本 |
|---|---|---|---|
| **A. 第 4 套主题** `data-theme="glass"` | 一整套新的背景/文字/描边 + 玻璃材质 | 现在 `dark/light/eye` 三态 | **最高**：16 色 × 4 主题 = 64 条配色规则，门禁口径全改 |
| **B. 材质开关** `data-material="glass"` | 主题/强调色都不变，只把"结构层"从实心面换成毛玻璃 | 现有 `GLASS LAYER` 已经是玻璃，只是默认强度受主题约束 | **最低**：一组令牌覆盖 + 一个开关 + 2 条门禁 |
| **C. 第 17 个强调色** `data-accent="glass"` | 只多一个色点 | 现在 16 色，已有 `glasswhite` | **最低但语义错**：玻璃不是颜色，且三白已覆盖"白" |

**我的判断**：
- 你要的"玻璃风"如果指的是**界面质感**（半透明、模糊、光晕、镜面高光）→ 走 **B**。
- 如果指的是**一整套新的观感皮肤**（连配色一起换）→ 走 **A**，但要注意它与 `eye` 主题的定位会重叠（都是"非纯黑纯白"），且维护成本翻倍。
- **不建议 C**：`glasswhite` 已经在色板里，再加一个"玻璃色"用户分不清，且会让"材质"和"颜色"两个轴混在一个下拉里。

> 下面按 **B（推荐）** 给完整方案，最后附 A 的差异清单。

---

## 二、方案 B 的实现（材质开关，与 3 主题 × 16 色正交）

### 2.1 现状已被验证过的地基（不用重造）

`ui.html` 的 `GLASS LAYER`（1443-1699）已经把玻璃拆成三层光学，并定义了全部令牌：

```
--frame / --chrome / --chrome-solid / --card / --card-hover
--rim / --rim-strong / --well / --edge / --glow / --blob-2
```

且已有三条护栏（DESIGN.md A11 §3）：
- 玻璃只给**结构层**（顶栏 / 页签胶囊 / 弹窗 / 浮层）
- 卡片只用"半透明面 + rim + 投影"，**不用 blur**
- 日志区 / 终端区 / 投屏画面**绝不盖玻璃**
- 降级：`prefers-reduced-motion` 停漂移；`prefers-reduced-transparency` 全部退回 `--surface` 纯色

**所以"玻璃风"不是从零做，而是"把现有玻璃参数推到一档更明显的强度"。** 这是成本低的关键原因。

### 2.2 具体改法（4 步）

**第 1 步：加一个正交属性**
```html
<html data-theme="dark" data-accent="blue" data-material="glass">
```
不放进 `data-theme`，因为它和明暗是两条轴（和 `data-accent` 正交的道理一样）。

**第 2 步：加一层令牌覆盖**（追加在 GLASS LAYER 内，或做成第 7 个注入层 `_v18.css`）
```css
/* 材质：玻璃风 —— 只覆盖"面"的四个令牌，不动文字色 */
:root[data-material="glass"]{
  --glass-blur: 34px;              /* 默认 26px，加大 */
  --glass-sat: 200%;               /* 默认 180% */
  --glass-rim: .22;                /* 镜面高光更明显 */
  --glass-tint: .42;               /* 半透面比默认更透 */
}
:root[data-material="glass"] .topbar,
:root[data-material="glass"] .tabs,
:root[data-material="glass"] .quick-nav{
  -webkit-backdrop-filter: blur(var(--glass-blur)) saturate(var(--glass-sat));
          backdrop-filter: blur(var(--glass-blur)) saturate(var(--glass-sat));
}
:root[data-material="glass"] body::before{ opacity:.9; }   /* 让光雾更明显 */
```

**第 3 步：UI 入口**
放进设置抽屉的「显示」区，做成三档分段控件（**实心 / 玻璃 / 跟随系统**），和主题卡同一种交互，避免再开新弹层。
落点：`ui.html` 设置抽屉（V12 区域）+ 新 `prefs` 字段 `material`（复用现成的 `prefs` 不透明串，C# 不用改协议）。

**第 4 步：降级优先级（必须显式定义，否则会打架）**
```
prefers-reduced-transparency: reduce  >  data-material="glass"
```
即：用户开了无障碍降透明，玻璃一律退回纯色；`data-material` 不得覆盖它。
实现上把现有的 `@media (prefers-reduced-transparency:reduce)` 块**放在玻璃规则之后**（保持现在的位置即可），并把玻璃规则的选择器加上 `:not([data-material="solid"])` 之类不影响优先级的写法 —— 关键是**不要再加 `!important`**。

### 2.3 性能护栏（这条不遵守会掉帧）

| 规则 | 原因 |
|---|---|
| 只给结构层，日志/终端/投屏区禁止 blur | `backdrop-filter` 每帧重采样，盖在滚动内容上必掉帧（DESIGN 红线三） |
| 卡片不加 blur，只加 rim + 投影 | 快捷指令几十张卡，每张一个 blur 层 = 合成层爆炸 |
| 光雾只动 `transform`，不触发重绘 | 现有实现已满足（`body::before` 52s 漂移） |
| 玻璃层数上限 | 一屏内同时可见的 blur 层 ≤ 4（顶栏、页签、设置抽屉、一个浮层） |

### 2.4 可访问性（必须做，否则就是"好看但看不清"）

玻璃面上的文字对比度**不能按 `--text` 直接算**，要先算合成底色：
`effective = tint * tintColor + (1-tint) * backdrop`

要求：
- 正文对合成底色 **≥ 4.5:1**
- 非文本 UI（描边、图标）**≥ 3:1**
- `--glass-tint` 的取值由 `_gen_accent.py` 参与计算（每色 × 每主题算一次，取满足对比度的最大透明度）

这条正好可以复用现有生成器的**单循环双约束**思路（现在是"accent 对表面 ≥3:1 且 on-accent ≥4.5:1"），加第三个约束即可。

### 2.5 代价清单（方案 B）

| 项 | 改动 | 工作量 |
|---|---|---|
| 令牌 + 3 个选择器 | `_v18.css`（新层）或 GLASS LAYER 内追加 | 0.5 天 |
| 注入脚本 | `_inject_v18.py`（照抄 v17，幂等） | 0.2 天 |
| 设置抽屉 UI | 三档分段控件 + prefs 字段 | 0.3 天 |
| 对比度计算 | `_gen_accent.py` 加第三约束，重出 `ACCENT-CONTRAST.md` | 0.5 天 |
| 门禁 | `_check_glass.py` 加 3~4 条（玻璃风下 blur 存在、卡片无 blur、降级优先、tint 对比度）；`_test_interaction.py` 加 1 条（切 material 后 `data-material` 正确） | 0.3 天 |
| 文档 | 手册「显示」章节 + DESIGN.md 加一条红线 | 0.2 天 |
| **合计** | | **约 2 天** |

## 三、方案 A（第 4 套主题）的额外代价

如果确定要"整套皮肤"而不只是材质，在上面基础上还要：

| 项 | 影响 |
|---|---|
| `THEME_ORDER` | `['dark','light','eye']` → 加 `'glass'`，**动了功能定义**（DESIGN 红线 1：主题是功能不是样式） |
| 配色规则 | `_gen_accent.py` 从 16×3=**48 条 → 16×4=64 条** |
| 门禁断言 | `_gate_invariants.py` 的「48 条 主题×色 令牌规则齐备」→ 64；`_check_accent_dom.py`(13 项)、`_check_glass.py`(20 项)、`_check_v12/v13` 里凡断言"三主题"的都要扩 |
| 持久化 | `SaveThemePreference` 白名单、`App.THEME` 三态判断（`== "light" || == "eye"` 这类**逐处散落**，容易漏）→ 建议先抽成 `IsLightLike(theme)` |
| 文档 | `ACCENT-CONTRAST.md` 64 行、手册主题章节、`DESIGN.md` A11 说明 |
| **额外工作量** | **+1.5 天**，且每次加/改色都要重算 64 条 |

**风险提示**：`glass` 主题与 `eye`（护眼暖白）在"非纯黑纯白"的定位上会重叠，用户可能分不清该选哪个。若两者都留，建议 `glass` 只做**深色系玻璃**（因为它需要后景光雾才有层次，浅色玻璃容易发灰）。

## 四、我的建议路线

1. **先做 B 的"最小可验证版"**（0.5 天）：只覆盖 `--glass-blur/--glass-sat/--glass-tint/--glass-rim` 四个令牌 + 顶栏/页签/设置抽屉三处，加到 GLASS LAYER，先看真机观感。
2. **看观感再决定要不要 A**：如果三处已经够"玻璃"，就不动主题轴；如果用户还想要"整套氛围"，再走 A。
3. **无论 A 还是 B，都把对比度计算挂进 `_gen_accent.py`** —— 否则以后每加一个色/主题都要手工验一遍可读性，迟早翻车。

---

## 五、需要你确认的三件事

1. 你要的"玻璃风"是**材质质感**（B），还是**一整套新皮肤**（A）？
2. 玻璃风是**独立一档**（实心/玻璃/跟随系统），还是**默认就开着、用户可关**？
3. 是否允许它在**浅色主题下也生效**？（我建议：浅色下只做"半透面 + rim"，不做强模糊 —— 浅底模糊容易发灰，且对比度更难达标）

确认后我按 B 出 `_v18` 原型并跑门禁；如果选 A，我会先把散落的"三态主题判断"抽成纯函数再动，避免漏改。
