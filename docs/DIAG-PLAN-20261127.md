# 诊断页改造清单（2026-11-27 确认版）

> 仅记录需求与核查结论，**未改代码**。11 条已逐条确认，可直接作为后续实施依据。

---

## 一、收缩项（现有内容）

### 1. adb 路径 / 来源：只在失败时展开

| 现状 | 要求 |
|---|---|
| 「连接状态」卡片常显 `路径`、`来源` 两行 | 仅当 `状态 = 失败` 时显示 |

**实施要点**

- 判断依据：`diagSetHealth('adb','bad',…)` 或 `状态` 行文案含「未找到」
- 正常时这两行不渲染；失败时整段展开，便于排查
- 「复制本块」仍包含完整信息（不受显示与否影响）

---

### 2. 本机 `.NET 版本`、`进程数`：界面不显示，只进复制报告

| 现状 | 要求 |
|---|---|
| 「本机信息」分组里平铺 | 界面移除，`diagCopySection('pc')` 输出里保留 |

**实施要点**

- 渲染时跳过这两个 key
- 复制逻辑单独走完整列表，不受渲染过滤影响
- 若用户手动展开「明细」也不显示（避免两处不一致）

---

### 3. 本机「设备名称」：删除

纯电脑名，无诊断价值。渲染与复制里都去掉。

---

### 4. 车机 `UUID` / `DID` / `OPENID`：折叠成一行

| 现状 | 要求 |
|---|---|
| 三行，值很长、经常为空 | 折叠为 `标识信息（3 项）`，点开才展开；复制时始终包含 |

**实施要点**

- 折叠行点击展开/收起（复用 `diag-card` 的 folded 交互思路）
- 展开后仍按 key 显示，空值显示 `—`
- 三项都为空时显示 `标识信息（未取到）`，避免占位空白

---

### 5. 资源占用：默认不采样，开启才刷新

| 现状 | 要求 |
|---|---|
| 3 秒刷新，进页面就采样 | **默认关闭**；用户开启后才采样，间隔 10 秒；不开启时显示空态 |

**实施要点**

- 卡片头部加开关（默认 off）
- off 时：不发起任何采样请求，行区显示「未开启采样，点击开关开始」
- on 时：立即采一次，之后 10s 间隔
- 离开页面自动停（避免后台空跑 adb）
- 首次开启仍保留「首次约 1~2 秒」提示

## 二、新增项

### 6. 一键体检（P0，最高优先）

页首增加结论条：

```
诊断结论：⚠ 2 项告警        （车机未 root、车机时间偏差 47s）
[查看问题]  [复制报告]  [重新体检]
```

**判定规则（首版）**

| 检查项 | 通过 | 告警 | 失败 |
|---|---|---|---|
| adb 可用 | 找到且能跑 | — | 未找到 |
| 设备连接 | device | offline / unauthorized | 无设备 |
| ROOT | 已 root | — | 未 root（视需求可降为提示） |
| 时间偏差 | ≤5s | 5~60s | >60s |
| 日志等级 | 已设置 | 未设置 | — |
| 崩溃计数 | 0 | 1~2 | ≥3 |

**理由**：35 个字段不会自己下结论，用户九成只想确认"现在能不能测"。

---

### 7. 崩溃 / ANR 计数（最近 5 分钟）

```
crash  2 次（最近 17:31 com.gxa.voice）
ANR    0 次
logd 丢弃  1.2%
```

**实现要点**

- 数据源：`logcat -d -b crash` + `logcat -d | grep ANR`
- 时间窗：最近 5 分钟（按日志时间戳过滤）
- 只统计计数与最近一条包名，不解析完整堆栈（避免卡顿）

---

### 8. 设备负载 top5

```
CPU   top1  com.gxa.voice      38%
内存  top1  com.gxatek.launcher 612 MB / 8 GB
```

**实现要点**

- `top -n 1 -b` 或 `dumpsys cpuinfo | head`
- 取前 5，按占用降序
- 与「资源占用」共用采样开关，避免重复拉起

## 五、一键部署 adb 核查（11）

**问题**：没有 adb 的情况下，「一键部署 adb」是否正常？

**结论：它不是"部署"，是"切换路径"。无 adb 且程序目录也没有内置 adb 时，功能不成立。**

### 代码事实

按钮链路：`diagInstallBuiltinAdb()` → `post('diaguseadb')` → `GuiWeb.cs:2692`

```csharp
string builtin = Path.Combine(BaseDirectory, "platform-tools", "adb.exe");
if (!File.Exists(builtin))
{
    PushOnUi("... ok:false, text:\"程序目录下没有 platform-tools\\adb.exe\"");
    break;                       // ← 到此为止，没有任何解压/下载兜底
}
App.ADB = builtin;               // 只是把 ADB 指向这份文件
App.ADB_SOURCE = "内置 platform-tools";
```

即：**只切换指针 + 读一次版本号**，不安装、不解压、不重启 server、不重新探测设备。

### 启动时其实已经自动找过

`Program.cs ResolveAdb()` 的候选顺序：

```
① PATH 里的 adb
② 程序目录\adb.exe
③ 程序目录\platform-tools\adb.exe
④ 上级目录\platform-tools\adb.exe
⑤ LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe
⑥ 各盘符 \platform-tools\adb.exe / \adb\adb.exe
```

所以**绿色包（含 platform-tools）解压即用**，用户不需要点这个按钮；
按钮实际是"手动纠正"用途。

### 真正会失败的场景

| 场景 | 结果 |
|---|---|
| 绿色包 + 系统无 adb | ✅ 启动自动用内置的，按钮也用得上 |
| 单 exe（无 platform-tools 目录） | ❌ 按钮报"程序目录下没有 platform-tools\adb.exe" |
| dist 目录被裁剪（只留 exe + internal） | ❌ 同上 |
| 内置 adb 被杀软隔离 | ❌ 同上（提示准确，但无补救） |

### 建议（记录，未执行）

```
① 把 adb.exe 也内嵌进 exe（Embed 已有解压机制），按钮改成"释放并启用"
② 释放路径写到 %LOCALAPPDATA%\adb_Tool\platform-tools\
③ 释放后校验可执行（已读版本号，可复用），失败则提示杀软拦截
④ 按钮文案改成「使用内置 adb」或「部署内置 adb」，与实际行为一致
```
