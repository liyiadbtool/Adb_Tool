## 已修复并验证

### BUG-20261128-CMD-01【P0】`:syslog` / `:fullog` 假成功：报"成功 N 项"但目录为空

- 位置：`_cs/MapCmds.cs:261 DoLogBundle()`
- 原因：`pull` 是**主机侧** adb 命令，却用 `ShellCapture()`（= `adb shell`）执行；设备返回 `sh: pull: not found`，
  而失败判定只认 `No such file / does not exist / error:`，`not found` 不在其中 → 计入成功。
- 修法：改 `AdbCall(new[]{"pull", remote, target})`，以**退出码 + 回执关键字**双判（新增 `not found`、`failed`）。
- 真机验证（b09acfa2）：
  ```
  :syslog → 成功 3 项，跳过 1 项
  跳过原因：rc=1  adb: error: failed to copy ... remote open failed: No such file or directory
  ```
  修前同一场景会显示"成功 4 项"且 `androidlog/` 目录为空。
- 回归项：F-61 导出文件数核对；`_cs/build.bat` 编译；`-selftest` 499 条

### BUG-20261128-BUILD-01【P0】CLI 编译断裂（GUI 编译掩盖）

- 位置：`_cs/Wireless.cs:123`
- 原因：catch 分支调用 `AdbLogExport.Gui.GuiEntry.Dump(...)`，而 GuiEntry 是 GUI 独有类型，不在 `_cs/build.bat` 的编译清单里
  → **CLI 直接编不过**。日常只跑 `build_gui.bat`，`--fast` 的 `-selftest` 又用的是旧 exe，因此长期未被发现（假绿）。
- 修法：改为不依赖 GUI 的 `Console.WriteLine`。
- 验证：`_cs\build.bat` → Compile success；`adb_log_export.exe -selftest` → 断言 499 条 0 失败。

### BUG-20261128-GATE-01【P1】功能清单机检 4 项假红

- 位置：`_check_features.json`（2 处 `[cmd.stoffline]`、`THEME_ORDER` 断言）、`_check_features.js`（占位符扫描）
- 原因：
  - `stoffline` 已在 16cb2fd 被替换为 `stengmode`，断言未跟
  - `THEME_ORDER` 增加 glass 后断言仍旧 3 档
  - 占位符扫描把注释里的"占位符替换"当残留
- 修法：断言跟到 4 档 / `stengmode`；占位符扫描跳过注释行
- 验证：`verify_all.py --fast` → 5/5 PASS
