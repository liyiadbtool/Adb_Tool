# 网联服务_Adb_Tool 用户使用手册

> 版本：2026-11-15（Apple UI 全面替换 + 3 项交互修复）
> 适用平台：Windows 10 / 11（自带 .NET Framework 4.x 即可，无需安装运行库）
> 适用设备：Android 车机 / 手机（需开启 USB 调试）

---

## 1. 这是什么

一个面向车机测试的 **adb 图形化工作台**。把平时要在命令行里敲的一长串 adb / shell 命令，做成了点一下就执行的按钮，同时提供：

- 多槽并行执行命令（最多 3 个输入框同时跑）
- 一键截图 / 录屏 / 导日志 / 导 HCI，自动按 `桌面\logcat\<日期>\<分类>` 归档
- 车机九项信息（车型 / SOC / MCU / Android / VIN / UUID / DID / OPENID / 分辨率）一键读取
- APK 管理：维护自己的应用清单，按包清空数据、关进程、导 APK、批量查版本
- 无线 adb：填个 IP 就能脱离 USB 线
- 设备插拔自动重连，断线自动切离线

命令行版本（`adb_log_export.exe`）与图形版共用同一套命令实现，行为完全一致。

## 2. 安装与启动

### 2.1 三种包

| 包 | 大小（zip） | 内容 | 什么时候用 |
|---|---|---|---|
| **单文件版** | 约 0.5 MB | **只有一个 exe**（界面 + 依赖 + 默认配置全在里面） | 首选。发给同事最不容易出错，拷一个文件就能跑 |
| **最小包** | 约 0.8 MB | exe + WebView2 依赖 + `webview2\ui.html` + 两个 ini | 需要改界面/配置排查问题，或不想让它自动释放文件 |
| **完整包** | 约 38 MB | 最小包 + `ffmpeg.exe` | 「一键录屏」要开箱即用（截帧合成 mp4）时 |

> 表里的体积是 **zip 实测值**（2026-11-15 出包），每次出包会随 ffmpeg 版本略有浮动；
> 完整包解压后约 102 MB，大头就是那个 105 MB 的 `ffmpeg.exe`。
>
> 单文件版和最小包里都没有 `ffmpeg.exe`。录屏是唯一需要它的功能，
> 其它功能（命令、日志、APK、投屏、文件管理）完全不受影响。

**单文件版怎么来的**：界面、两个 WebView2 托管 dll、原生 `WebView2Loader.dll`、
`adb_log_export.ini` / `cmds.ini` 的默认值都编译进了 `adb_Tool.exe`。
运行时：托管 dll 走内存加载，原生 loader 释放到 `%LOCALAPPDATA%\adb_Tool\native\`，
界面释放到 `%LOCALAPPDATA%\adb_Tool\ui\ui.html`，缺失的 ini 才写出一份默认值。

**外置优先**（三类资源都一样）：程序同级有同名文件就用外部的，没有才用内嵌的。
所以想把界面改一下，把 `webview2\ui.html` 放回 exe 同级、改完重启即可，不用重新编译；
想换 SDK dll 也一样。ini 更是"只要存在就绝不动"。

### 2.2 启动

1. 把整个文件夹解压到**有写权限**的位置（桌面、D 盘都行，**不要放 C:\Program Files**）
2. 双击 `adb_Tool.exe`
3. 首次启动 Windows 可能提示「已保护你的电脑」→ 更多信息 → 仍要运行
4. 车机用 USB 线连电脑，车机上弹出「允许 USB 调试吗」→ 勾选「一律允许」→ 确定

启动后左上角会依次亮起：

- `root` 胶囊：绿色 = 已提权，红色 = 未提权（可点），灰色 = 设备未连接
- `无线` 胶囊：绿色并显示 IP = 无线已连上
- 设备号 · SOC · 分辨率：连上就会显示

### 2.3 目录结构

```
adb_Tool.exe                 主程序（单文件版就这一个）
webview2\ui.html             界面（可选：没有就用 exe 内嵌的）
Microsoft.Web.WebView2.*.dll WebView2 依赖（可选：同上）
WebView2Loader.dll           同上（可选：会释放到 LocalAppData）
adb_log_export.ini           主配置（缺失时自动写默认值）
cmds.ini                     自定义命令（缺失时自动写默认值）
使用手册.md                   本文档
ffmpeg.exe                   （可选）录屏用
```

> 标"可选"的文件**删掉也能跑**（单文件版就是全都没有）。
> 保留它们的好处：出问题时可以直接改、直接看，不用碰 exe。

│                                                                                  │

`Ctrl+1`~`Ctrl+4` 依次切「指令 / 终端 / 文件 / 投屏」；`UI` 页点页签进入（暂未设快捷键）。

### 3.1 输出区（底部）

- **默认收起**，只留一条 34px 的「▼ 输出」栏
- **只有你自己能打开**：命令执行（哪怕有输出、哪怕失败）都不会自动展开，避免打断正在看的页面
- 打开方式：点折叠栏 / 从折叠栏往上拖；收起方式：表头「收起」按钮或 `Alt+↓`
- 收起时折叠栏右侧显示条数（`输出 · 12 条记录`），失败还会弹一条 toast
- 展开后右上角四个按钮：`仅失败` / `复制全部` / `清空` / `收起`

### 3.1.1 主题（三套）

右上角圆形按钮循环切换，**顺序：黑夜 → 白天 → 护眼 → 黑夜**，选择会记到 `adb_log_export.ini` 的 `theme=`，下次启动自动恢复。

| 模式 | 配色 | 图标 |
|---|---|---|
| 黑夜 | 深灰蓝底（默认） | 绿色月亮 |
| 白天 | 白底 | 橙色太阳 |
| 护眼 | 暖白底 `#fdfaf3`、低蓝光 | 眼睛 |

- 切到白天/护眼时，Windows 标题栏也会跟着变浅（不会出现白底黑标题栏的割裂感）；
- 投屏画面是设备原图，**不跟随主题变色**。

### 3.2 顶栏

| 元素 | 说明 |
|---|---|
| `root` | 绿色=已提权；红色=未提权，点一下执行 `adb root`；灰色=设备未连接 |
| `无线` | 点开填 IP → 连接；连上后显示 IP，点击可断开 |
| 设备号 / SOC / 分辨率 | 连上设备自动带出 |
| `日志 V` | 设备当前日志等级（`persist.log.tag`）。**五种等级五种颜色**：V 紫 / D 蓝 / I 绿 / W 橙 / E 红。在线但设备没设这个属性时显示灰色「未设置」（不再整块消失，避免看着像少了一项）；离线才隐藏。想显示就在终端执行 `setprop persist.log.tag V` 后重连 |
| `执行中 00:12 [停止]` | 任何页签都能看到，点停止只停当前这一条 |
| 🌙/☀ | 深色 / 浅色主题切换 |

## 4. 终端页

- 输入框里敲命令，**回车执行**，输出就显示在这个输入框下方的日志区里（不跳页）
- 切换到本页时输入框**自动获得焦点**，打开就能敲，不用再点一下
- `cd` 只切换目录（提示「已进入 /data」），**不会自动列目录** —— 想看内容自己敲 `ls`
- `↑` `↓` 翻历史命令
- 右侧按钮：`执行` / `停止` / `清屏` / `复制`
- 点输入框左边的 `+` 可以再加输入框（最多 3 个），**多个输入框可以同时跑命令**，输出各在各的框里，互不串台

> 输出落在哪一页：在「终端」页敲的，留在本页日志区；在「指令」页敲的（搜索框下方那条输入、或点卡片），
> 进下面的输出区（反馈表）。两个地方互不干扰。

### 4.1 常用输入规则

| 输入 | 行为 |
|---|---|
| `ls` / `cd /data` / `pull` / `push` | 与 adb shell / adb pull 完全一致 |
| 任意 shell 命令 | 原样透传给设备 |
| `:xxx` | 工具内置命令（见第 13 节） |
| `C:\Users\...\Desktop` | 纯 Windows 路径 = 把当前设备目录导出到这里 |
| 纯中文 | 当作语音意图发送（见 `:send`） |

## 5. 指令页

左侧是按场景分好的组：`指令执行`、`方控按键`、`手车互联`、`语音助手`、`APK管理`、`网络模拟`、`自定义命令`。

- 点卡片 = 执行；执行中卡片变转圈，再点（带进度的卡）可停止
- 右上角搜索框（`Ctrl+K` 聚焦）：按名称 / 说明 / 命令模糊搜，回车跳到第一条
- `Ctrl+1` / `Ctrl+2` / `Ctrl+3` / `Ctrl+4` 依次切到「指令」「终端」「文件」「投屏」，「UI」点页签
- 一条命令执行期间不能点第二条（互斥，避免抢 adb）
- 部分分组不是卡片网格而是**表单面板**（`APK管理`、`网络模拟`），选中分组后显示对应面板，卡片网格自动隐藏

### 5.1 自定义命令（cmds.ini）

在 `cmds.ini` 里加一段即可出现在「自定义命令」组，**不用改程序**：

```ini
[cmd.mycmd]
desc = 一句话说明
group = 我的命令
usage = mycmd <参数>
run = shell "dumpsys battery | head -5"
```

支持占位符：`$1..$9`、`$*`、`$(date)`、`$(time)`、`$(serial)`、`$(cur)`。

### 5.2 SynTestUtil 功能（并入指令执行）+ 网络模拟表单

2026-11-14 从 SynTestUtil 逆向来的高频动作，命令全在 `cmds.ini` 的 `[cmd.st*]` 段里，改命令不用改程序。
2026-11-15 按参考图重构：**删除独立的「测试工具箱」分组**，11 张卡并入「指令执行」并用小标题分类；「网络模拟」改成参数表单面板。

**「指令执行」组里新增的三类小标题**

| 分类 | 卡片 |
|---|---|
| 日志与取证 | 抓全日志（`stlogall`）、抓系统日志（`stsyslog`）、抓TCPdump数据（`sttcpdump`） |
| 显示与信息 | 开启坐标 / 关闭坐标（`stxyon` / `stxyoff`）、查看VIN（`stvin`）、网络状态-ping（`stping`）、网络状态-IP（`stip`） |
| 配置入口 | 日志配置（`stlogcfg`）、账号助手（`staccount`）、下线配置（`stoffline`） |

要点：抓全日志是一次性导出 logcat 当前缓冲最近 2000 行（长时采集用终端页 `:sid` / `:dlog`）；
抓TCPdump 抓 200 个包直接回显，不落 pcap；`stoffline` 若跳转失败（`Error type 3`），改 `cmds.ini` 里它的 `run` 即可。
点卡片即执行，输出在下方反馈表。

**「网络模拟」表单面板**（按 SynTestUtil 弱网/代理参考图重做）

选中「网络模拟」分组后不再显示卡片，而是一个带「预置环境值 / 自定义环境值」、上下行参数表和操作按钮的表单：

| 区域 | 内容 |
|---|---|
| 预置环境值 | 无弱网（恢复）/ 2G 弱网 / 3G 一般 / 高延迟 / 高丢包；选完自动填好下面的参数 |
| 参数表 | 网络速率 (kbps) / 延迟 (ms) / 丢包率 (%)，各有「上行」「下行」两列 |
| 配置代理 / 开启 / 关闭 | `stproxyget` 查询代理；「开启」把当前**上行**参数折成 `stweak <延迟>ms <丢包>% <速率>kbit` 下发；「关闭」下发 `stweakoff` 删 qdisc |
| 代理地址 | 填 `IP:端口` 后点「开启代理」(`stproxyon`) / 「关闭代理」(`stproxyoff`)。**必须三键一起删**，只删 `http_proxy` 会留 host/port 残值 |
| 大输出框 | 记录每次下发了什么命令，便于 QA 追溯；设备真实回显仍在下方反馈表 |

- 所有按钮都走指令页既有的 `quick` 通道（`post('quick', cmd)`），**没有新增消息协议**，命令本身仍由 `cmds.ini` 定义；
- `tc netem` **需 root** 且车机内核要支持 `sch_netem`；它只作用于 `wlan0` 出口（上行），**下行列用于记录设计参数**，不是对称生效；
- 代理服务本身（mitmproxy 监听 8888）要在 PC 侧自己起，本工具只负责下发车机上的 `settings` 命令。

完整命令对照、证据来源与待上机确认项见 `docs\SynTestUtil命令对照与用法.md`。

## 6. APK 管理

这一页解决「我要针对某个应用做操作，但不想每次手打包名」。

### 6.1 维护应用清单

1. 点右上「＋ 管理列表」
2. 填 **名称**（随便写，中文/英文都行，下拉里显示的就是它）和 **包名**（如 `com.gac.user.center`）
3. 点「保存」；列表里每行右侧有「删除」

规则：

- 名称和包名都不能重复（重名会提示是谁占了）
- 包名必须是 `com.xxx.yyy` 这种带点的形式，只允许字母、数字、点、下划线
- 数据存在 `%LOCALAPPDATA%\adb_Tool\apk_apps.txt`，**关掉程序下次还在**，也可以直接用记事本编辑
- 第一次运行会从 `adb_log_export.ini` 的 `version_pkgs` 自动导入一次

### 6.2 选应用

点左上角下拉框 → 只显示**名称**；输入文字可过滤（名称和包名都参与匹配）；`↑` `↓` 选择，`Enter` 确认，`Esc` 关闭。
每项右侧的 `×` 可以直接从清单里删掉。

### 6.3 三个主操作（针对选中的应用）

| 按钮 | 实际命令 | 说明 |
|---|---|---|
| **清空数据** | `pm clear <包名>` | 清空**全部**应用数据（登录态、授权、缓存都清），应用回到刚安装状态。系统级应用可能因权限失败，需要先 root |
| **关闭进程** | `am force-stop <包名>` | 只杀进程，数据完整保留 |
| **导出APK** | `pm path` + `pull` | 导出到 `桌面\logcat\<日期>\APK`。多 split 应用会把 base 和 split 一起导出（**不打包**，安装时要用整个目录） |

> 注意：**「清空数据」不是清缓存**。清缓存只删 `cache` 目录，需要 root；这个按钮清的是全部数据。

### 6.4 前台指令（原来那四条完整保留）

| 按钮 | 等价命令 | 说明 |
|---|---|---|
| 查前台应用 | `:front` | 前台包名 + Activity + 路径 + **pid**（无进程则不显示 pid） |
| 查询前台包名 | `:front` | 只查前台包名与 Activity |
| 清理前台应用 | `:fstop` | `pm clear` 前台应用 |
| 导出前台APK | `:apk` | 导出前台应用的 APK |

另有两个辅助按钮：

- **查前台**：查出当前前台应用，并自动在下拉里选中它
- **加入列表**：把当前前台应用加进清单（包名自动填好，只需起个名字）

### 6.5 批量查版本

点「查询全部版本」→ 一次 adb 调用查完清单里所有包，每条显示：

```
个人中心   3.2.1.261026
com.gac.user.center
/data/app/~~ab==/com.gac.user.center-yy==/base.apk
```

- 没装的包显示 `未安装`（灰色），不会让整次查询失败
- 应用**有进程时**版本后面会跟 `pid 12345`（多进程会列出多个），没有进程则整段不显示
- 面板上原来有两个"查前台"按钮（一个走 `:pkg now`、一个走 `:front`），现在**只保留一个**，行为等于 `:front`
- 底部汇总：`共 N 个，未安装 M，用时 1.8s`
- 「复制全部」= 复制成 TSV（名称 / 包名 / 版本 / 路径），贴进 Excel 自动分列
- 「删除」= 清空下方所有输出

### 6.6 输出区规则

- 每次操作**新开一段**，历史结果留在上面可以往回翻 ——
  查完版本再执行别的指令，**版本结果不会被冲掉**
- 最新一段会自动滚到可见位置；最多保留最近 12 段

## 7. 文件管理（双栏）

第三个页签，左边是电脑、右边是设备，两边都能直接拖到对面。

### 7.1 左栏「此电脑」顶层

最上面三个 ★ 是**快捷入口**，省掉逐层点点点：

```
★ 桌面      → C://Users//<你>//Desktop
★ 下载      → C://Users//<你>//Downloads
★ 文档      → C://Users//<你>//Documents
▸ C:        盘符仍然完整保留
▸ D:        ...
```

- 路径取的是系统的“已知文件夹”，**OneDrive 重定向过桌面也能正确指向**
- 某个目录不存在（比如没下载文件夹）就自动不显示，不影响盘符
- 双击进入后，`↑` 会回到它的上一级（如 `C://Users//<你>`）

### 7.2 基本操作（树形）

左右两栏都是**树**，不是"一层层进去"：

| 操作 | 行为 |
|---|---|
| 单击文件夹 | 展开 / 收起（首次展开才去读目录） |
| 单击文件 | 只选中 |
| 双击文件夹 | 展开它，并折叠其它同级（聚焦这一支） |
| 双击空白 | 全部收起 |
| `⇱` 按钮 | 全部收起 |
| 拖到**文件夹行**上 | 复制到该文件夹（拖到空白处不响应） |
| 拖到对面一栏的行上 | 左→右=上传，右→左=下载 |
| 从资源管理器拖进本页 | 上传到设备当前目录 |
| 单节点超过 500 项 | 出现「还有 N 项，点这里加载更多」 |

- 缩进每级 14px，`▸/▾` 表示可展开/已展开（目录不再重复画第二个三角，名称尽量靠左）；
- **两栏中间的分隔条可拖动**，文件内容看不全时把左/右栏拉宽；
- 顶部路径栏显示**当前选中项**的完整路径（选中文件时显示其所在目录）；
- 刷新保留展开状态；无权限目录在节点内显示红字提示，不影响其它分支；
- 选中文件夹时，「新建文件夹」建在它里面；选中文件时，建在它所在目录。

### 7.2.1 传输进度

- **单文件**：按**字节**推进度，显示 `62%  12.4 MB / 20.0 MB  文件名`；
- **整个文件夹**：按文件个数推进度（`3/7`）；
- 拖到某个文件夹行上时，**该行整行高亮**；传输开始/完成会立刻取消高亮与面板遮罩；
- 传输完成后**自动刷新目标目录**，新文件立即出现；
- 传输中可点「取消」，正在传的那个会中断（已传完的不回滚）；
- 完成态停留 400ms 再消失，小文件也能看见。

### 7.2.2 搜索（左右各自独立）

每栏的路径栏里有一个搜索框：**左边只搜电脑，右边只搜设备**，两个框互不影响。

| 操作 | 行为 |
|---|---|
| 输入关键词 | 停顿 0.4 秒自动搜（也可按回车立刻搜） |
| 结果 | 平铺列表，每行右侧灰字显示它所在的目录；顶部是`共 N 条 · 耗时 · 搜索范围` |
| 单击结果行 | **进入树状结构**：退出搜索态、清空搜索框、把从根到该目标的整条祖先链逐级展开、选中并渲染它。目录行左侧有 ▸ 箭头，和平时在树里点开文件夹的方式一致，没有额外按钮 |
| 双击结果行 | 同上（保留兼容，老习惯双击也能进树）；不会重复发起搜索 |
| Esc | 清空关键词、回到树 |
| 结果里拖拽 | 可以拖到对面栏的文件夹行上复制；**搜索态的那一栏不接收落点** |

- **搜索范围**：左侧取"当前选中的目录"（不选就是所有固定盘），右侧默认 `/sdcard`；
- **深度**：本地 8 层、设备 6 层；**上限 500 条**，超了顶部提示"已截断"，加个关键词就窄了；
- 设备侧不显示大小/时间（每条都去 stat 会把 adb 排队排满），点结果行进树里就能看到；
- 无权限的目录会被跳过，不会让整次搜索失败。

> 设备重连后，右侧会**自动清缓存并重新拉取**根目录（以前设备没连上时进文件页，
> 右侧会一直红字报错，必须切页或重启才恢复）。

### 7.3 新建 / 重命名 / 删除

每栏底部三个按钮，作用对象是**该栏当前路径 + 选中项**：

- **新建文件夹**：在当前路径下建
- **重命名**：只有选中 1 项时可用
- **删除**：会弹确认框，删除后不可恢复

### 7.4 进度与取消

- 复制时顶部出现进度条和 `3/7 my log.txt` 这样的文字
- 期间可以点「取消复制」，正在传的那个文件会被中断（已完成的不回滚）
- 正在复制时再次拖拽会被拦住，避免并发抢占 adb

### 7.5 三条要知道的规则

1. **同名不覆盖**：两边已有同名文件时，自动加时间戳改名（`a.txt` → `a_20261113_203045.txt`）。
2. **`/data`、`/system` 需要 root**：没提权时右栏会显示「没有权限读取该目录（需要 root）」，点顶部 `root` 提权后再刷新。
3. **拖出到资源管理器做不到**：这是 WebView2 的平台限制。要下载就用「拖到左侧电脑栏」，或者先进入目标目录再拖。

## 8. 投屏（多屏同时看）

第四个页签。把车机的主屏 / 副屏 / 后排屏 / HUD / PHUD-B / PHUD-C 共 6 格同时显示在工具里。

### 8.1 用法

1. **进页面自动探测屏位**（`dumpsys display`），不再需要手动点「刷新屏位」；
2. 「主屏」（第 1 格）和「后排屏」（第 3 格）已**内建屏位映射**：主屏固定绑 displayId 0、后排屏固定绑 displayId 1，直接点「开启」即可，不用先选下拉；
3. 其余格子在下拉里选一块屏（默认按顺序分配），点「开启」；
4. 画面出现后格子边框变绿，标题栏显示 `屏 N · X fps · 耗时`；再点一次「停止」结束该路。

**内建的主屏 / 后排屏**

上一版的「前排投屏」「后排投屏」「刷新屏位」三个按钮**已删除**，能力直接落进固定格子：

- 主屏（槽 0）→ displayId 0；后排屏（槽 2）→ displayId 1。依据 SynTestUtil 投屏脚本里写死的 `--display-id=1`；
- 探测列表里能找到该屏就用它，找不到（比如某些车型只上报 1 块屏）就**退化为按顺序分配**，其它车型仍可用，不会静默失败；
- 下拉没选时点「开启」也会用这个内建映射兜底；
- 画面**留在工具页面里**，不弹 scrcpy 独立窗口，主窗口焦点不变，可以边看边点画面、录屏、切页。

> 需要 scrcpy 的高帧率时，每格右下原有的「外部」按钮仍可用（已支持 `--display-id=N`）。那是**你显式选择**才切出应用，跟内建投屏互不冲突。

**点击画面 = 点车机**

直接点画面上的位置，就等于在那块屏上点了一下（`input tap`）。

- 坐标按该屏真实分辨率换算，黑边（letterbox）上的点击会被忽略；没探测到分辨率时用帧自身的尺寸兜底；
- 只对**已开启**的格子生效，未开启/离线时不发；
- 每次点击在画面上留一个蓝色涟漪，确认"这一下发出去了"。

**点击更跟手**（2026-11-15 优化）

点一下要等挺久才看到变化，是这套截帧投屏最容易挨骂的地方。这轮做了四处：

- 25ms 内同一格的重复点击（触控板/触摸屏鬼影）自动合并，不再往消息队列里堆；
- 后端改成**丢弃式队列 + 单后台线程**：连点时只保留每格最新一次 tap，不排队等前面的 adb 子进程；
- tap 落地后**立刻唤醒采集循环抓一帧**，不用等完整的帧间隔睡完；
- 涟漪改用动画结束事件自清理，连点不再堆定时器。

> 注意：这优化的是「点击后的响应延迟」，不是把画面变成视频级帧率。
> 内置通道仍是 1.5~3fps 的截帧预览（见 8.2）。要看流畅动画请用「外部」scrcpy。

**投屏图片不再跟着鼠标拖**

浏览器对 `<img>` 默认会生成一张半透明的拖拽预览图（drag ghost），跟着鼠标走，容易让人误以为能把文件拖进投屏格。
已关掉：`<img>` 设 `draggable=false` + CSS `user-drag:none`，并在画面容器上拦了 `dragstart`。文件复制请走「文件」页的左右双栏。

**全屏 + 底部缩略条**

- 点格子右上角 `⤢`（或双击标题栏）→ 该格**全屏**，其余已开启的路在**底部条**里显示实时缩略图；
- **点底部缩略图** = 与全屏互换（不重启采集，其它路继续刷新）；
- **已开启**的槽在底部显示**实时画面**缩略图；**未开启**的槽显示**「开启」按钮**，点一下就地开起来；
- 关掉正在全屏的那一路 → 自动退出全屏；
- 再点 `⤡` 或双击标题栏还原。

**拖分隔条调大小**

- 格子之间的竖线、横线都能拖（鼠标移上去变亮），用来调列宽/行高；
- **最大化不影响其它格**：用的是浮层覆盖而不是隐藏，其它格的流一直在跑，
  还原后立刻就是最新画面，不需要重连（早期版本用 `display:none`，会导致被隐藏那路的
  `<img>` 流被浏览器挂起，看起来像"扩大一下别的投屏就停了"）。

### 8.2 帧率说明（重要）

| 屏 | 实测帧率 | 单帧大小 |
|---|---|---|
| 主屏 2560×1440 | ~1.5 fps | ~130 KB |
| 副屏 1920×720 | ~2.8 fps | ~35 KB |
| 后排 800×480 | ~3.0 fps | ~35 KB |

**它不是 30fps 的视频投屏，是 1.5~3fps 的"看画面"级预览。** 原因有两条：

- 这台车机的 `screenrecord` 对主屏/副屏**输出 0 字节**（受保护面），只有 800×480 那块能录，
  所以拿不到 h264 视频流；
- 转 h264 要 ffmpeg（105 MB），会破坏"最小包也全功能"。

所以走的是 `screencap` 逐帧抓 + 本地流转发：**零依赖、最小包也能用**，代价是帧率低。
看 UI 布局、看有没有卡死、看日志弹窗够用；要看流畅动画不行。

### 8.3 录制

每格一个「录制」按钮：

- 点击开始，`screenrecord` 录该屏到设备，最长 60 秒（再点一次提前停）；
- 停止后自动拉回到 `桌面\logcat\<日期>\screenrecord\cast_<槽位>_<时间>.mp4`；
- **部分屏不支持**（同上，主屏/副屏可能录出 0 字节），失败会明确提示，不会留空文件。

**录屏编码器（ffmpeg）怎么配**：车机屏幕带 `FLAG_SECURE`，`screenrecord` 取不到帧，
所以真正能用的录屏是"截帧 + ffmpeg 合成 mp4"。ffmpeg 有 105 MB，不打进包里，由你自己提供。
工具会自动按四步找它（每找到一处都会先跑 `ffmpeg -version` 验真）：

| 顺序 | 位置 |
|---|---|
| 1 | `adb_log_export.ini` 里的 `ffmpeg=` |
| 2 | `adb_Tool.exe` 同级（含 `ffmpeg\bin\ffmpeg.exe`、`bin\ffmpeg.exe`） |
| 3 | 系统 `PATH` |
| 4 | 常见安装位置（`%LOCALAPPDATA%\adb_Tool`、`C://ffmpeg`、Program Files、scoop、chocolatey） |

投屏页右上角有一个状态芯片：

- **绿点 + 版本号**（如 `ffmpeg：6.1.1 · 程序同级`）= 可用，鼠标悬停看完整路径；
- **红点 + 未找到** = 点右边的「选择…」直接挑 `ffmpeg.exe`，工具会校验并**自动写回 ini**，下次不用再选；
- **「重新查找」** = 忽略缓存重扫一遍（刚装完 ffmpeg 时用）。

命令行等价操作：

```
:ffmpeg                      看当前用的是哪一个、从哪找到的
:ffmpeg auto                 强制重新查找
:ffmpeg D://ff//bin//ffmpeg.exe   校验并记住这个路径
```

### 8.3.1 外挂 scrcpy（可选，流畅通道）

内置投屏走的是"连续截帧"，实际约 3fps —— 够看画面，不算流畅。
如果电脑上有 `scrcpy.exe`，可以点每一格右下角的 **「外部」** 按钮，
用 scrcpy 单独开一个窗口看那一屏（几十 fps，可操作），内置通道继续跑，互不影响。

| 状态 | 表现 |
|---|---|
| 找到 | 芯片显示 `scrcpy：2.4`，点「外部」直接开窗 |
| 没找到 | 芯片显示 `scrcpy：未找到（可选）`，点「外部」会提示原因，**继续用内置通道** |
| 找到但启动失败 | 弹窗/提示里给出 scrcpy 的原话（比如老版本不支持 `--display-id`），同样不耽误内置通道 |

查找顺序与 ffmpeg 一致：`ini 的 scrcpy=` → 程序同级（含 `scrcpy\scrcpy.exe`）→ `PATH` → 常见位置；
每一项都会跑 `scrcpy --version` 验真。也可以点「选择…」手动指定，会自动写回 ini。

> 为什么要单开窗口：scrcpy 的画面是它自己渲染的，没有稳定接口能塞进本工具的界面里。
> 硬做内嵌要么自己实现 h264 解码，要么截它的窗口再贴图（掉帧且不能交互），
> 所以这里选择"能用就用它，不能用就用内置"，不做半成品。

### 8.4 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 画面全黑 | 该屏受 FLAG_SECURE 保护，采集到的是黑帧 |
| 点了开启但画面空白 | 旧版本的一个 bug：`/live/0?t=时间戳` 里的查询串没被服务端剥离，导致槽位解析失败、连接被直接关掉。已修复（`-casttest` 里有专门断言） |
| 一直"连接中" / 格子全黑 | 设备掉线时旧版本会一直挂着。现在连续 5 次取不到帧会自动停，并显示"设备离线或该屏不可采集，已停止"；重新插好设备后切走再切回「投屏」页会重新探测屏位，再点「开启」 |
| 点击画面没反应 / 感觉迟钝 | 该格未开启、设备离线，或点在黑边上；若觉得「点了要等一下才变」，见 8.1 的「点击更跟手」——内置通道本来就是 1.5~3fps 的截帧预览，不是视频流 |
| 拖动画面时出现半透明图片 | 旧版浏览器的默认拖拽预览。已关掉，见 8.1 末段；要复制文件请用「文件」页 |
| 只有 3 块屏 | 车机实际只上报了 3 个 display，PHUD 可能复用了后排的显示通道 |
| 录制失败 | 该屏 `screenrecord` 无输出，改用截图或换屏 |

## 9. UI 对比（第五个页签）

「投屏」右侧的 **UI** 页签。按 SynTestUtil「UI 对比」参考图的布局重做，用来把**设计图**和**实景截图**叠在一起看偏差、标出差异像素。

实现上全部在浏览器里算：**文件选择用 File API，叠加 / 差异用 Canvas 逐像素算**，不引入 Python / PIL，不新增 C# 消息 kind，图片**不出本机**。参考图里那种「填路径 + 打开结果图」改成了「选本地文件 + 本页生成 + 导出 PNG」。

### 9.1 界面

| 区域 | 控件 | 作用 |
|---|---|---|
| 图片路径 | 「选择…」+ 只读路径框 + 透明度滑块 | 选设计图（PNG / JPG）。设计图会同时作为实景栏的**叠加层**；透明度 0~100%，默认 100% |
| 本地图路径 | 「选择…」+「直接截图」+「后屏截图」 | 选实景图；两个截图按钮见 9.2 |
| 参数行 | 实景图透明度、是否标记差异（是 / 否）、差异阈值（默认 30 / 255） | 选「否」只做叠加对齐、不标红；阈值越大越不敏感 |
| 中部双栏 | 设计图 / 实景图（叠加设计图对齐） | 左栏看原设计，右栏看实景 + 半透明设计图叠加层（叠加层取设计图透明度的一半，避免盖死实景） |
| 结果行 | 结果图路径、「2016车机是否需要打开」、「开始对比」、「打开结果图」 | 生成本页结果图并显示差异占比；「打开结果图」导出 PNG |
| 结果区 | 结果图 | 以实景图为底，差异像素标红 |

> 「2016车机是否需要打开」是参考图里带过来的记录项，本工具**不驱动车机**，它不参与对比运算，仅保留便于 QA 对照用例。

### 9.2 两个截图入口

| 按钮 | 实际行为 |
|---|---|
| 直接截图 | 下发 `:shot`（走指令页既有的 `quick` 通道），截图落到 `桌面\logcat\<日期>\screencap\`。**不会自动填进对比框**，执行后去该目录用「选择…」把它选为实景图 |
| 后屏截图 | 取「投屏」页**后排屏**格子（槽 2）的当前帧，显示在实景栏用于对齐。要求该格已开启 |

**后屏截图只能用于预览，不能直接算差异**：那一帧来自 `http://127.0.0.1:<端口>/live/2` 的实时投屏流，Canvas 读它的像素会被浏览器按跨域拒绝。要正式对比，请把截图保存为本地文件再「选择…」。代码里已经拦住并给出提示，不会静默出一张错图。

### 9.3 开始对比

1. 选好设计图和实景图，调透明度对齐；
2. 选「是 / 否」标记差异，必要时调阈值；
3. 点「开始对比」→ 结果区出图，结果图路径显示 `本页生成 · 宽×高 · 差异 x.xx%`，并弹一条 toast 给出差异像素数；
4. 点「打开结果图」导出 `ui_compare_<时间戳>.png`。

计算口径（不藏着）：

- 取两张图**较小**的宽高作为对比区域，超出部分不参与 —— 所以最好用同分辨率的截图，否则差异占比会偏小；
- 逐像素比 RGB 三通道绝对差之和，大于 `阈值 × 3` 记一个差异像素；
- 结果图以**实景图为底**，命中的像素做偏红处理；选「否」时只叠加不标红；
- 差异率是「命中像素 / 对比区域像素」，**不是** UI 还原度评分，也不做结构 / 文字识别。

### 9.4 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 提示「读图失败 / 跨域限制」 | 用了「后屏截图」的实时帧直接对比。先存成本地文件再「选择…」，见 9.2 |
| 提示「先选择设计图和实景图」 | 两栏都选了本地文件才算数，只截图预览不算 |
| 差异率明显偏小 | 两张图分辨率不一致，按较小尺寸裁掉了多余区域 |
| 结果图一片红 | 阈值调太低，或两张图根本没对齐；先调透明度对齐，再调高阈值 |

## 10. 无线 adb

适用：车机 USB 口不方便长期插线，或需要移动测试。

### 10.1 连接

1. **先插 USB**（第一次必须有线，tcpip 要从本地连接发出去）
2. 点顶栏 `无线` → 浮层里填车机 IP（可留空自动取），端口默认 5555
3. 点「连接」，等 3~8 秒

期间会发生：

- 车机 adbd 重启，USB 会瞬断 1~3 秒（**这是正常的**，界面不会报"设备断开"）
- 连上后 `无线` 胶囊变绿并显示 `192.168.x.x:5555`
- 输出区会打一行 `√ 已连接 ...，可以拔掉 USB 了`

### 10.2 断开

点 `无线` → 「断开」。也可以在指令页敲 `adb disconnect`。

### 10.3 失败怎么办

| 提示 | 处理 |
|---|---|
| 取不到设备 IP | 车机可能没连 WiFi；手动填 IP |
| adb tcpip 失败 | 车机 ROM 不支持无线调试；换 USB |
| 连接后设备没出现在 adb devices | 换端口试，或确认电脑和车机在同一网段 |
| 拔掉 USB 后掉线 | 正常现象，重新插 USB 再连一次 |

> 无线下导大日志会明显变慢（逐文件传输），**导日志请优先用 `:dlog`**（设备端先打包再拉）。

### 11.1 导出"部分成功"是什么意思

活动日志目录里的文件在实时轮转（写满就删旧的）。逐文件拉取时，可能在拷贝途中文件被删掉，出现：

```
adb: error: failed to copy '.../xxx.txt.z' to '...': remote open failed
```

这时工具会报 **「部分成功：已导出 N 个文件，M 个没拉下来」**，并自动补拉一次。
**不是整次失败**，已经落地的文件都是好的。

想彻底避免：用 `:dlog`（设备端先 `tar` 打包成快照再拉一个文件）。

## 12. 常见问题

**Q：插上设备没反应 / 没自动连上**
1. 车机上确认「USB 调试」已开，并在弹窗点「允许」
2. 换一根**数据线**（很多线只能充电）
3. 关掉其他占用 adb 的程序（Android Studio、手机助手、其他 adb 工具）
4. 指令页敲 `:r` 手动刷新
5. 仍不行：看 `%LOCALAPPDATA%\adb_Tool\logs\gui_trace.log`，搜索 `watcher:` 关键字

**Q：root 一直是红的**
- 设备没授权或 ROM 不允许 `adb root`（部分量产机默认关闭）
- 点一下红色 `root` 胶囊手动提权，看输出区的失败原因

**Q：清空数据失败**
- 系统级应用不允许 `pm clear`，先 root
- 包名写错：用「查询全部版本」确认是否已安装

**Q：导出 APK 后装不上**
- 该应用是多 split 包，`APK` 目录里的 base.apk + split_*.apk 要一起装（用 `adb install-multiple`），只有 base 装不上

**Q：录屏点不动 / 报找不到 ffmpeg**
- 用的是最小包，把 `ffmpeg.exe` 放到 exe 同级即可（或在 ini 里 `ffmpeg=路径`）

**Q：界面全白 / 打不开**
- 确认 `webview2\ui.html` 与 exe 在一起
- 系统需装 WebView2 运行时（Win11 自带；Win10 可能需装一次）

## 18. 自定义 ADB 指令（2026-11-15 新增）

位置：**指令执行页 → 左侧「自定义」分组**（第 7 组）。

### 18.1 新建一条

点「＋ 新建指令」，填三个框：

| 框 | 必填 | 说明 |
|---|---|---|
| 名称 | ✅ | 显示在卡片标题上，例如「重启车机语音」 |
| 说明 | ⬜ | 卡片副标题；**不填就整行不显示**，不会留空白 |
| adb 命令 | ✅ | 支持**多行**，每行一条，按顺序执行 |

命令框下面可以往流程里插「官方节点」：

- **延时**：填毫秒，执行到这一步就等这么久（做「点完等界面刷新」很有用）。
- **循环**：填次数（≥2），把**上一条 adb 命令**重复这么多次。

规则（不满足会当场红字提示，存不进去）：

1. **第一行必须是 adb 命令**，不能一上来就是延时 / 循环。
2. **官方节点之间必须隔一条 adb 命令** —— 连续插两个节点没有意义，会被拒。
3. 节点上面那条命令不能是空的：先把命令写了，再加节点。

保存后，卡片出现在「自定义」分组里，点一下就跑。

### 18.2 执行时的行为

- 多行命令**按顺序一条条下发**，前一条结束才发下一条。
- **某条失败不会中止**：跳过它继续跑后面的；失败的原生回显（adb 自己的报错）
  照常出现在底部输出区，不另外加工文案。
- 循环节点重复的是「上一条命令」；命令框里写了多行时，重复的是**最后一行**。
- 跑完弹一条 toast：`自定义流程结束：成功 N / 失败 M`。

### 18.3 编辑与删除

卡片墙下方是已保存列表，每行有「编辑」「删除」。编辑会回填名称、说明和整个流程；
删除有二次确认。配置存在 `%LOCALAPPDATA%\adb_Tool\custom_cmds.b64`，
换机器时把这个文件拷过去即可（也可以整份备份）。

## 19. 本轮稳定性修复（值得知道的三条）

1. **命令框里敲 `q` / `quit` / `exit` 不会再关掉工具了**。
   以前这三个词会直接结束进程，而且不写任何日志 —— 表现就是"工具在任务栏里突然消失"。
   现在界面模式下会提示「界面模式下不执行退出命令」，要关请直接关窗口。
2. **投屏卡住会自动放弃，不会拖死整个工具**。单帧截图 8 秒拿不到就杀掉那个 adb 进程，
   连续 5 次失败会把该屏标成「已停止 + 原因」，其它功能照常。
3. **关窗口会先停投屏采集**，不再留下后台 adb 进程（任务管理器里不会攒一堆 `adb.exe`）。

| 功能 | 怎么用 |
|---|---|
| 新建标签 | 「＋」或 `Ctrl+N` |
| 打开文件 | 「打开」或 `Ctrl+O`，支持 txt/log/ini/sh/bat/json/xml 等纯文本 |
| 保存 | `Ctrl+S`；未命名会弹保存框 |
| 另存为 | `Ctrl+Shift+S` |
| 关闭标签 | 标签上的 ×；有未保存改动会问一句 |
| 查找 | `Ctrl+F`，`Enter` 下一个 / `Shift+Enter` 上一个，显示「第 n / 共 m」 |
| 替换全部 | `Ctrl+H` |
| 跳行 | `Ctrl+G`，填行号 |
| 自动换行 | `Alt+Z` 开关 |
| 字号 | `Ctrl+滚轮` 或状态栏 `A-` / `A+`（10–28px） |
| 撤销 / 重做 | `Ctrl+Z` / `Ctrl+Y` |
| 行号 | 左侧固定栏，跟随滚动 |

### 22.2 三条规则（重要）

1. **编码原样保留**：打开时识别 UTF-8 / UTF-8 BOM / GBK / UTF-16 LE，
   保存时**写回同一编码**。拿 GBK 的 ini 改完存回去不会变乱码。
2. **换行原样保留**：原来是 CRLF 就还是 CRLF，LF 就还是 LF。不会出现「改一个字整份文件 diff 全红」。
3. **2MB 上限**：超过 2MB 的文件会提示改用外部编辑器（避免界面卡住）。
   日志文件建议直接用输出区的「导出」功能，不要走文本页。

未保存的标签在标题前有 `●`；关工具时如果有未保存内容会拦一下。

「指令」页第三组，六个屏一条一个：

| 卡片 | 命令 | 屏 |
|---|---|---|
| 主屏投屏 | `scrcpy --display-id 0` | 中控主屏 |

| 后排屏投屏 | `scrcpy --display-id 1` | 后排屏 |
| HUD 投屏 | `scrcpy --display-id 3` | HUD |
| PHUD-B 投屏 | `scrcpy --display-id 9` | PHUD-B |

命令行等价写法：`:scrcpy 0` / `:scrcpy 9`，也认中文名（`:scrcpy 主屏`、`:scrcpy PHUD-C`）。

1. **主屏也显式传 `--display-id=0`**。上一版是 `if (displayId > 0)` 才传参，于是主屏反而不带参数，

2. **窗口标题带屏名**（`adb_Tool · 后排屏`）。同时开六个窗口时，任务栏里能分清谁是谁。
3. **只投屏、不接管输入**（`--no-control`）。测试机上误触会改车机状态，这个风险不值得冒。

### 26.5 scrcpy 安装与"装好了却提示找不到"

推荐一条命令装（本机已装 5.0.1）：

```
winget install --id Genymobile.scrcpy -e --source winget
```

装完**不用重启本工具**。原因：winget 只改注册表 PATH，而已经在跑的进程读到的还是启动那一刻的旧值 ——
所以这一版在探测 scrcpy 时同时读了两处：

1. 进程环境变量 PATH；
2. 注册表 `HKCU\Environment` 与 `HKLM\...\Session Manager\Environment` 里的 PATH；
3. 再直接扫 `%LOCALAPPDATA%\Microsoft\WinGet\Packages\Genymobile.scrcpy_*\scrcpy-win*\scrcpy.exe`。

> 第 3 条是关键：winget 的 portable 包**不一定**在 `WinGet\Links` 里放 shim，
> 5.0.1 实测就没有。只靠 PATH 会一直提示"未找到"。

没有 scrcpy 也不影响用：内置截帧通道照旧，只是帧率低（约 3fps）。

### 27.1 从底部 dock 打开时窗口很小、点不动

**现象**：从任务栏图标点开，窗口出现时只有巴掌大一块，内容全挤在里面，也没法输入。

**根因不是"尺寸算错了"，而是"用改窗口尺寸的方式做动画"**。旧实现 `PlayOpenAnim()`
的做法是：先 `SetWindowPos` 把真窗口缩到 168×100，再分 11 帧往目标尺寸放大。这条路有三个必现故障：

1. **目标是读运行时 `Bounds` 得来的**。动画跑到一半又被触发一次（点两下图标、从 dock 反复切），
   第二次读到的"目标尺寸"就是那个中间尺寸 —— 缩小会自我叠加，永远回不到正常大小。
2. **WebView2 初始化会堵住 UI 消息泵 1~3 秒**。这期间 `PostMessage`/`BeginInvoke` 排不进来，
   帧整段丢失，动画停在第 1~2 帧的尺寸上。
3. **任何中断都停在中间尺寸，而且不会最小化**。所以用户看到的是一个"矮窗口"，不是"没打开"。

还有一个帮凶：为了允许窗口缩到 160×96，`WM_GETMINMAXINFO` 里的
`ptMinTrackSize` 被放宽到了 `1`。这等于把系统级的下限保险关掉了 —— 任何残留下来的
`SetWindowPos` 都能把窗口钉在小尺寸上。

**改法**：**不碰窗口尺寸**。

- 窗口一步到位（`OnShown` 里定尺寸），动效交给内容层：给 `#frame` 加 `.v16-in`，
  就是 `opacity .001→1` + `transform:scale(.94)→1`，200ms `cubic-bezier(.2,.8,.2,1)`。
  缩放的是**渲染层**，窗口真实尺寸全程不变，中断了最多是"淡入没播完"，绝不会留下小窗口。
- `ptMinTrackSize` 恢复成 `MinimumSize`，系统层面不再允许缩到不可用尺寸。
- 加 `EnsureSaneBounds()` 兜底：`OnShown`、`WM_ACTIVATE`（重新激活）、以及尺寸异常时各调一次。
  它先 `RefreshSane()` 记一份"最近一次正常尺寸"到 `_sane`，发现当前 `Bounds` 小于
  `MinimumSize` 就用 `_sane` 拉回来；`_sane` 本身也不合法才按屏幕工作区居中开一个 1100×760。
- 整段尺寸动画（`DockRect` / `AnimateBounds` / `PlayOpenAnim` / `PlayMinimizeAnim`）全部删除，
  最小化改成直接的 `WindowState = FormWindowState.Minimized`。

> 怎么自查：`python _v16_checks.py` 里有 8 条专门盯这件事，其中一条是
> "`DockRect|PlayOpenAnim|PlayMinimizeAnim|AnimateBounds` 一个都不能出现"。

### 27.2 强调色增加纯白、护眼白、玻璃白（13 → 16 色）

色板现在是 16 个点，4×4 排（5 列会溢出面板）。新增三个：

| 色名 | 深色主题下 | 浅色 / 护眼下 |
|---|---|---|
| 纯白 `purewhite` | `#FFFFFF` | `#939393`（正灰） |
| 护眼白 `eyewhite` | `#FFFDF5` | `#9C9284`（暖灰） |
| 玻璃白 `glasswhite` | `#E9E9EE` | `#8E949E`（冷灰） |

**为什么浅色下不能用白**：强调色要压在浅色表面上，还得保证上面的文字能读。
直接把 `#FFFDF5` 压到 3:1，会得到 `#AA8E8E` —— 那点 1% 的暖调被放大成玫瑰灰；
`#E9E9EE` 的冷调会被放大成土黄。所以三白在浅色 / 护眼下走了另一条路：
先按 `(色相, 饱和度)` 在 HLS `L=0.62` 处起算（纯白 sat=0 → 正灰；护眼白 `(42°, .10)` → 暖灰；
玻璃白 `(220°, .08)` → 冷灰），再由原有的压暗循环压到刚好 3:1。

改的是生成器 `_gen_accent.py`（`NEUTRAL` 表 + 16 色 `ORDER`），48 条规则全部重新生成，
每条都同时满足"对表面 ≥3:1"和"其上文字 ≥4.5:1"。`--on-accent`（勾的颜色）仍是按亮度自动选黑或白。

> 注意 `ACCENT_ORDER` 是个隐藏门槛：色名不在这个数组里会被**静默回退成 blue**，
> 哪怕 CSS 规则齐全也一样。加色时必须同时改三处：生成器 `ORDER`、`ACCENT_ORDER`、`Program.cs` 的 ini 白名单。

### 27.3 投屏指令并入「指令执行」，分类统一「投屏」

独立的「投屏（scrcpy）」分组删掉了，6 张卡（主屏 / 副屏 / 后排屏 / HUD / PHUD-B / PHUD-C）
并进「指令执行」，卡片小标题统一成「投屏」。这样搜索框一搜 `投屏` 就是一个整齐的分类，
不用在两处找。

投屏页右上角另加了「**用 scrcpy 打开**」按钮（`castOpenScrcpy()`）：它按你在页面上选中的那块屏，
直接发 `:scrcpy <displayId>`。内置通道帧率不够时，一键换到 scrcpy 原生窗口。

### 27.4 弹窗互斥：一次只显示一个，后开的抢占先开的

**现象**：日志等级弹窗和设备弹窗会同时出现、互相压字；有时弹窗被切掉一半。

**根因**：两个弹窗原来是挂在徽章（`.logpill` / `#dev-badge`）**里面的**。而
`.titlebar` 和 `.tabs` 各自有 `backdrop-filter`，会**各自形成层叠上下文** —— DOM 里靠后的
`.tabs` 就会压住标题栏里的弹窗；徽章的祖先链上还有 `overflow` 裁剪，于是"显示不全"。
旧的 `.v15-pop` 用 `right:0; top:calc(100%+9px)` 定位，这两个值也只在"弹窗是徽章后代"时才成立。

**改法**：弹窗搬到 body 级 `position:fixed` portal。

- `attachPop(p, which, anchor)`：`p.style.position='fixed'` + `zIndex=9800`，
  `document.body.appendChild(p)`，记下 `popCur = which` 和锚点，然后 `placePop()` 算坐标。
- `placePop()`：默认贴锚点下方 9px；下方放不下就翻到上方；左右溢出就贴边；`max-height` 限在视口内并自身滚动。
- **互斥靠单例 `popCur`**：`openLogPop()` 进来先看 `popCur==='dev'` 就 `detachPop` 掉设备弹窗，
  反之亦然。所以"后开的抢占先开的"，任何时刻只有一个。
- 关闭统一走 `closeAllPops()`（Esc、点外部、切页都调它）。
- `.v15-pop` 改成 `display:none` + `.on{display:block}`。**不能用内联 `style.display=''` 复位** ——
  空字符串会落回 CSS 的 `display:none`，弹窗永远不显示。
- 窗口 resize / 滚动 → `repositionPops()` 重新算位置，不会留在旧坐标上。

### 27.5 弹窗打开时不再冒 hover 提示

`bindHover` 只监听徽章的 `mouseenter`。弹窗开着时，鼠标移到弹窗上仍然算在徽章范围内，
60ms 后顶部又浮出一条提示，和弹窗内容叠在一起。

修法一句话：`showTip()` 开头 `if (anyPopOpen()) return;`。

### 27.6 设备弹窗显示不全

和 27.4 是同一个根因（挂在被裁剪的祖先里），改完 portal 就一起好了。
另外 `.v15-pop` 现在自带 `max-height:calc(100vh - 20px)` + `overflow:auto`，
设备多了也不会顶出屏幕。

### 27.7 投屏还是低帧率、卡顿

先说结论：**内置通道的天花板在"每帧都要从设备搬一张整图"，不在编码**。
这一轮做了四件事，其中第一件最后被数据否掉了，留在这里当记录。

**① 抓帧两条路，选快的（原以为 raw 一定赢，实测不一定）**

- `screencap -p`：设备端压 PNG。弱 CPU 车机要 ~400ms，但传过来的数据小。
- `screencap` 不带 `-p`：拿原始 RGBA，设备侧几乎不耗 CPU，但要搬 `w*h*4` 字节。

原计划是"一律走 raw"，实测反而更慢：这台机器是**无线 adb，约 8MB/s**，1600×900 的 raw 单帧 5.7MB，
光传输就要 700ms+；raw 734ms 输给了 png 656ms。USB3 上结论会反过来。

所以改成**自适应**：每个屏第一次抓帧时两条路各测一次，选快的并固定下来（raw 允许 15% 容差，
避免两台机器之间来回抖）。`LastGrabPath` 会打印实际走了哪条，`-castprobe <displayId>` 可以直接看数字。

**② 帧格式从 PNG 改成 JPEG**，本地编码：R/B 交换 → 缩到 1280 宽（双线性，不用 Bicubic，
Bicubic 在高频界面文字上会出彩边）→ JPEG q72。`Publish` 只校验 JPEG 签名 `FF D8 FF`，
不按体积卡（全黑小图可能只有几百字节）。MIME 三处同步改成 `image/jpeg`。

**③ scrcpy 补画质参数**：`--max-size=1600 --max-fps=60 --video-bit-rate=16M --no-audio --print-fps`。
两个坑：

- `--stay-awake` 与 `--no-control` **互斥**，5.0.1 会直接报
  `Cannot request to stay awake if control is disabled` 然后退出。所以去掉。
- `--print-fps` 每秒往 stderr 写一行，但**没人读 stderr**。Windows 管道缓冲 4KB，
  写满后 scrcpy 阻塞在写 stderr 上 —— 表现是"投屏几分钟后画面卡死"。现在起后台线程
  `ReadLine` 把 stderr/stdout 抽干，顺便把带 `fps` 的行写进 trace。

**④ 非 0 屏首帧失败就停**：副屏 / HUD 之类不一定支持 `screencap -d`，首帧失败就立刻停并提示
"该屏不能用 screencap 采集，请用 scrcpy 外部窗口"，不再傻等。

**实际帧率**：无线 adb 上约 1.5fps，USB3 上明显更高。界面上写的是
"内置通道 1~5fps（看链路，无线 adb 更慢）"，不吹数字 —— 要流畅就用 scrcpy 那个按钮。

> 想真正到 30fps，得走 h264 流 + 页内解码（MSE）。这条明确不做，原因是它把整条链路的
> 复杂度抬一个量级（编码参数、关键帧、延迟补偿、解码失败恢复），而 scrcpy 已经把这件事做好了。

### 27.8 记忆用户设置（字号 / 日志等级 / 显示选项 / tab 顺序）

问题不是"没存"，而是"存了不读"：`prefsApply` 只认 `font / custom` 两个字段；
字号在 v14 层又自己解析了一遍（补丁式写法，注释里都写着"得自己再解析"）；
`logshow` 只写不读；显示选项（跟随系统 / OLED / 护眼）压根没进 prefs。

改成**一份 schema 一次吃完**（`_v16.js` §1）：包一层 `window.prefsApply`，把
`size / logshow / oled / eye / auto / tabOrder` 全交给 `applyAllPrefs()`。
`applyDisplay()` 写回时也补上 `oled / eye / auto`，`v15Snapshot()` / `v15Restore()`
负责显示三项的存取。字号恢复走 `applySize(size, true)` 的静默通道，不弹 toast。

### 27.9 tab 可拖拽换位并记忆

按住任意 tab 横向拖，松手就停在新位置；关掉应用再打开，顺序还是新顺序。

实现要点（`_v16.js` §2）：

- 用 **pointer 事件**，不用 HTML5 `draggable` —— 后者在 WebView2 里长按有系统延迟，手感粘。
- **6px 死区**：位移小于 6px 就是普通点击，不能把"切 tab"误判成拖拽。
- `document.elementFromPoint` 找当前压在哪个 tab 上，`insertBefore` 实时换位（拖着就能看到让位）。
- 松手后浏览器还会补一个 `click`，必须吃掉（`suppressClickUntil = now+160`），否则会顺带切到被拖的 tab。
- 顺序写进 `_prefs.tabOrder`，回填走 `applyTabOrder()`；换完调 `v15SyncTabOrder()`
  让翻页方向（`TAB_ORDER`）跟着重算，否则翻页会按旧顺序翻。
- 拖拽期间 `body.v16-tabdrag` 禁选中、并且 `animation:none !important`，避免和翻页的 transform 打架。

### 27.10 新增 9 条 adb 查询指令

都在「指令执行」的「系统查询」分类下，命令定义在 `cmds.ini`：

| 卡片 | 实际命令 |
|---|---|
| 查 adb 版本 | `adb version` |
| 内存总览 | `shell "dumpsys meminfo \| head -40"` |
| 屏幕密度 | `shell "wm size; wm density"` |
| 屏幕参数 | `shell "dumpsys window displays \| head -80"` |
| Android ID | `shell settings get secure android_id` |
| Android 版本 | `shell getprop ro.build.version.release` |
| 已连接设备 | `adb devices` |
| 启动 adb 服务 | `adb start-server` |
| 停止 adb 服务 | `adb kill-server` |

顺手修了两处名不符实：`[cmd.mem]` 原来只取 30 行，看不到 Total PSS 以下的进程，改 40 行；
`[cmd.screen]` 名字叫"屏幕密度"但只跑了 `wm size`，现在 size 和 density 一起给。

> **`adb root` 没有加**。它会重启 adbd，把正在跑的日志抓取和投屏全部断掉，
> 副作用远大于收益；要做"停止 adb 服务"用 `kill-server`（同样会断连接，需要 `:r` 重连，
> 卡片描述里已写明）。

### 27.11 快捷指令搜索加强（为指令越堆越多做准备）

有搜索框之后"分类"其实不再重要，搜得到就行。但原来的搜索是**整串子串匹配**，
搜 `reboot` 找不到"重启车机"（它的命令是 `adb reboot`，名字里没这个词）。

现在（`_v16.js` §3）：

- **一次性建索引**：每条卡的 `name / desc / cmd / cat / alias / kw / 所属分组` 拼成小写 hay，
  存在 `HAY[组][序]`。数据变了（自定义命令增删）用 `v16InvalidateQuick()` 让它失效。
- **空格分词，全命中才算中**：`adb log 抓` 三个词都要在。
- **加权排序**：命中位置越靠前分越高（`<24` 得 3 分、`<80` 得 2 分、否则 1 分），同分保持原顺序
  —— 稳定，结果不会跳来跳去。
- **结果上限 80 条**，再多也没人翻。
- **80ms 防抖放在事件入口**（`v16QuickInput`），`onQuickSearch` 保持同步。
  这一条踩过坑：一开始直接替换了 `window.onQuickSearch` 做防抖，结果任何同步调用者
  （测试、代码里直接调）都要等 80ms 才见结果，表现是"点了没反应"。防抖只该挡连续击键。

实测：搜 `reboot` 命中 3 条（"重启车机"排第一）、搜 `adb 设备` 命中"已连接设备"、
搜 `kill-server` 命中"停止 adb 服务"。
