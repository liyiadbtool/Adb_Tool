# 投屏 6 格 + 指令补充 · 需求与排期（2026-11-19）

> 决策：投屏走 **scrcpy 协议**（scrcpy-server + WebCodecs），最多 6 格；沿用现有 6 格屏号配置。
> 已验证：接受「2 路流畅 + 其余缩略」的降级形态（若编码器不够）。

## 一、S0 实测结论（2026-11-19 17:15，T09M / 6dd4523c）

### 设备实际情况

| display | 类型 | 分辨率 | 可采集 | 说明 |
|---|---|---|---|---|
| 0 | 内置 | 2560×1440 @60 | ✅ | 主屏，scrcpy 正常出画面 |
| 2 | HDMI 外接 | 1920×720 @60 | ❌ | `FLAG_SECURE`，screencap 出 7KB 纯黑 PNG，scrcpy 0fps |
| 3 | HDMI 外接 | 800×480 @60 | ❌ | 同上 |

> **本机只有 3 块屏**，不是 6 块。6 格是 UI 容量上限（`Cast.cs` `MAX_SLOT=8`，界面 6 格），
> 对多屏域控车型才有意义；本台车机最多 3 路，其中只有 1 路有内容。

### 帧率

| 场景 | 结果 |
|---|---|
| 内置通道（screencap）现状 | **1.5 fps** |
| scrcpy 单路 1280/30 4M（画面变化连续） | **37~60 fps** |
| scrcpy 3 路并发（主屏 + 2 块黑屏） | 主屏仍 **30 fps**（打满 `--max-fps`） |
| 分辨率 640 / 960 / 1280 对比 | 帧率一致 → **不受分辨率限制** |

**结论**：scrcpy 方案在本机可行，主屏能从 1.5fps 提到 30fps（打 `--max-fps` 上限）。
编码器支持 3 路并发不掉帧。

### 踩过的坑（写进代码注释，别再踩）

1. `--no-window` / `--no-playback` 会让 scrcpy 报 `nothing to do`，且 `--print-fps` 失效。
   → 测帧率要开真窗口，用 `--window-x=-2400 --window-y=-2400` 挪到屏幕外。
2. 多实例默认共用同一个 server socket，第二个起不来（`Server connection failed`）。
   → 每路必须 `--port=27183+N`，并错峰 1.2s 启动。
3. `--print-fps` 打到 **stdout**，不是 stderr（用 stderr 捕获会一条都拿不到）。
4. 静态画面下 MediaCodec 不出新帧，`--print-fps` 显示 0 或 10 左右 ——
   **这不是设备上限**，要用连续长滑动（900ms）造帧才能测出真实能力。
