# DESIGN · Apple UI 替换沉淀的「别这么做」

> 来源：2026-11-15 Apple 设计语言全面替换（A0–A11 / B1–B5）。对应 A8 门禁 4 的 learn-taste 沉淀。
> 用途：下次改这个工具的界面之前，先读这 12 条。每条都是本轮真实踩过或差点踩过的坑。

---

## 一、功能与表现的边界

1. **别把「三套主题」当成可以合并的样式。**
   `dark / light / eye`、`THEME_ORDER`、`data-theme` 取值、宿主写回 `adb_log_export.ini` 的 `theme=` 是**功能**。
   任何「合并成明暗两套更简洁」的提议都算功能变更，必须停下来问。护眼态是 Apple 浅色 + 暖白低蓝光变体，不是第三套随便配的皮。

2. **别顺手改 `quickGroups` 里的命令、分组名或 `post()` / `onclick`。**
   本轮只把死数据 `color:'#xxxxxx'` 换成 `color:'var(--accent)'`，因为全文件没有任何地方读取 `.color`。
   **先证明字段没被读，再动**；反过来，凡是 `post()` 签名、`onclick=` 函数名、`case 'xxx'` 的 kind 字符串，一个字符都不改。

3. **别在「纯换肤」里夹带功能改动而不声明。**
   本轮用户同时要求修 3 个交互缺陷（底部缩略条黑屏 / 缺停止按钮 / 搜索进入方式）。
   这些需要改 JS 函数体和 `_cs/Cast.cs` 的 HTTP 端点，已经**超出 A10 的允许层**。
   正确做法是按 A9 追加轮登记新 ID、重算分母、在最终报告里显式写「超出纯换肤范围」，而不是假装它们只是 CSS。

## 二、颜色与图标

4. **别在组件样式里留硬编码色。**
   三态主题一换，写死的 `#e06c6c` / `#3fb99b` 立刻在某一套主题下变得刺眼或不可读。
   一律引用 `--err / --ok / --accent / --lv-*` 等语义令牌。令牌**定义处**出现 hex 是对的，组件规则里出现 hex 是错的。

5. **别写死颜色值到测试断言里。**
   本轮 4 个失败套件里有 3 个是旧断言写死了 `rgb(224,108,108)`、`#3fb99b`、`/live/1`。
   断言要检查**语义**：红通道是否显著占优且等于 `var(--err)` 的解析值、SVG 是否 `currentColor`、缩略条是否指向 `/snap/`。
   否则每次换皮都要改测试，测试就失去了保护作用。

6. **别让顶栏 / 加载层 / ico / 任务栏出现四个不同的品牌图形。**
   本轮统一成 Apple 单线终端 `>_`：SVG 源在 `icons/svg/`，7 尺寸 ico 由同一图形生成，exe 内嵌 `/win32icon` 必须重编译才会同步。
   图标颜色用 `currentColor` 跟随文字色，主题按钮三个 key 的**语义**（月亮=dark / 太阳=light / 眼睛=eye）不许改。

7. **别给投屏 `<img>` 加滤镜、主题色或圆角裁切之外的处理。**
   那是车机设备原图，是测试依据，不是装饰元素。只调容器外框。

## 三、交互与连接

8. **别给每个缩略图再开一条 `/live/<i>` 长连接。**
   主投屏格每个已开启槽已经占一条 multipart 长连接；全屏时底部条再复制一份同源连接，
   Chromium 对同一 host 的并发连接数一满，超过 2 路后底部就全黑。
   缩略图只要「看一眼当前画面」：`/snap/<slot>` 返回最近一帧 PNG、`Connection: close`，1 秒轮询只换 `img.src`、不重建 DOM（否则停止按钮会失效）。

9. **别把「进入下一级」做成一个额外按钮。**
   用户要的是「搜索到文件之后点击展开进入树状结构，和未搜索时的交互方式一致」。
   结果行加 `data-search="1"`、目录行给 ▸ 箭头、点整行调 `fsReveal` 展开祖先链，就够了。
   同时保留 dblclick 兼容，并用 `justRevealed` 时间戳挡住浏览器补发的 dblclick —— 否则单击刚展开的祖先链会被 `fsCollapseAll` 又整棵收起。

10. **别把「点击流畅」理解成提高帧率。**
    内置投屏靠 `adb exec-out screencap` 逐帧抓，约 2~4 fps，不是视频流。
    能优化的是**点击后的响应延迟**：前端 25ms 同槽连点合并、后端丢弃式 tap 队列、`tap` 后 `Kick` 立刻抓一帧。
    对外要说清这个口径，别承诺 30 fps。

## 四、流程与交付

11. **别只改 U1 就说出包完成。**
    `ui.html` 有 U1 源码 / U2 `dist` / U3 `dist_min` / U4 单文件 exe 内嵌 / U5 成品 zip / U6 成品目录外置位。
    本轮还改了 C# 和 ico，**必须跑 `release.py` 重编译**，只靠「外置优先」会让 `/snap` 请求 404、任务栏还是旧图标。
    也别把新版外置 ui.html 放进旧成品目录：旧 exe 没有 `/snap` 端点，那是功能倒退，应标 N·A 并写理由。

12. **别在没有门禁的情况下宣称 100%。**
    覆盖率、功能不变量、静态自检、16 项 DOM/CLI/GUI 门禁是四道独立的锁。
    `python _gate_invariants.py`（冻结层对照）、`python _build_inventory.py`（清单分母）、
    `node 377/_check_ui.js`、`node _check_features.js`、`python verify_all.py`、`python release.py` 缺一不可。
    分母由代码算，不手写百分比；N·A 逐条写理由，不用「等 / 其他 / 依此类推」。

## 本轮引用的技能口径（B1–B5）

- 应用定位：**Windows 桌面 · 工具型 / utility**，不是营销页、不是 iOS/macOS 原生 App。
- 因此：动效近乎不可见、spring ≤300ms、cinematic OFF、Bento 不套用。
- 权重最高：`apple-design-family`（HUB：Clarity / Deference / Depth）、`apple-design-foundations`（语义色 / 系统字体栈 / 8pt）、
  `apple-design-tactics`（WCAG 2.2 AA、44pt、三偏好降级、不靠颜色单独表意）、`apple-design-hig`（accessibility / layout / typography / color 常载）、
  `finesse-ui`（product register 的 audit / component-scope / redesign 只读流程）、`break-ui`（最坏数据补隐藏状态）。
- 明确不用：`apple-design-web`（营销滚动叙事）、`apple-design-os`（iOS sheets / detents）、`mobile-native`、
  `apple-design-backend`、`prototype`（仅图标候选）、`frame-smith` / `write-swift` / `animate-expo`。

## A11 轮设计说明（2026-11-15：9 色强调色 · 自定义指令 · Liquid Glass · 图标 v2）

### 1. 强调色与明暗主题是两条正交的轴
- `data-theme`（dark / light / eye）管背景、文字、描边；`data-accent`（9 色）**只**覆盖
  `--accent` / `--accent-soft` / `--on-accent` 三个令牌。
- 27 条 `:root[data-theme="X"][data-accent="Y"]` 由 `_gen_accent.py` 生成，
  包在 `/* === ACCENT LAYER START/END === */` 之间，可反复重跑而不会叠加。
- 取值用**单循环双约束**：同时满足「accent 对表面 ≥ 3:1」与「on-accent 文字 ≥ 4.5:1」；
  浅底一律压暗、深底一律提亮，每轮重算 `best_on`。
- 白 / 黑在对应背景上本来就不可见，自适应为 systemGray `#8E8E93`；eye 主题以 light 为基底降饱和 0.82。
- 证据：`docs/ACCENT-CONTRAST.md`（27 行对比度表）+ `_check_accent_dom.py`（13 项 DOM 实测）。

### 2. 自定义指令的流程语义（把「一行行编辑」翻译成可执行队列）
- 步骤只有三种：`cmd` / `delay` / `loop`。**第一行必须是 cmd**，且**节点之间必须隔一条 cmd**。
- `loop = 重复「上一条 adb 指令」n 次` —— 正因为节点必须间隔命令，这个语义没有歧义。
- 执行时把流程**展开成线性数组**，逐条复用 `post('quick', line)`，
  用输出流里的 `end` 消息驱动下一条。失败（`ok=false`）也继续推进 = **跳过**；
  失败命令的原生回显照旧进输出框，不另造错误文案。
- 持久化走 **base64 不透明 blob**：前端 `JSON → btoa`，C# 只存取不解析。
  原因是 `GetField()` 遇到 `/`、`,`、`}` 会截断，而 base64 字符集不含这三个字符。
- 校验文案分离：`第一行必须是 adb 命令，不能是官方节点`（首行是节点）与
  `第 N 行命令不能为空`（首行是空命令）是两回事，不能合并成一句。

### 3. Liquid Glass 的三层光学与三条红线
- 三层：**illumination**（半透明底 + `backdrop-filter: blur() saturate()`）、
  **highlight**（`inset 0 1px 0` 顶部镜面 rim）、**shadow**（落地投影）。
- **living backdrop** 是玻璃的前提：`body::before` 铺四团光雾并 52s 极慢漂移，
  只动 `transform`（合成层），不触发重绘。没有后景的玻璃只会发死灰。
- 红线一：玻璃只给**结构层**（顶栏 / 左侧导航 / 页签胶囊 / 弹窗 / 浮层）。
- 红线二：卡片几十张，只用「半透明面 + rim + 投影」，**不用 blur**。
- 红线三：日志区、终端区、投屏画面**绝不盖玻璃** —— 模糊层盖在持续更新的内容上必掉帧。
- 降级：`prefers-reduced-motion` 停漂移与 pop-in；`prefers-reduced-transparency` 全部退回 `--surface` 纯色。

### 4. 图标 v2：一个屏讲三个词
- 车载 = 圆角**中控屏面板** + 屏下**中控台底座**横条；测试工程师 = `>_`；联网 = 屏顶 **wifi 圆点 + 双层弧**。
- 亮度层级**只留一级高光**：提示符 1.0、信号弧 0.55、底座 0.34、面板 0.16。
  次要元素与主体同亮，是"看起来廉价"的最常见原因。
- **多尺寸美术分级**（Apple 对 16/32 单独出简化稿的惯例）：
  16px 去掉信号弧，只留底 / 面板 / 提示符 / 底座四块明度；
  24–32px 单弧且加粗到 3.2；48px 以上才上双弧与面板描边。
- 7 档 ico（16/24/32/48/64/128/256）+ 可编辑 SVG + 顶栏/加载层内联图形**同一几何源**，
  由 `_icon_v2.py` 一次生成，避免"四处各画一个"。

## A12 轮设计说明（2026-11-15：自绘标题栏 · 设置抽屉 · 全局字体 · 文本页）

### 1. 为什么必须自己画标题栏

第一反应是「给窗口设个深色标题栏」—— 这条路走不通，原因是可验证的：

- 像素采样证明原生 DWM 标题栏在**深色和浅色主题下都是纯黑 `(0,0,0)`**，标题文字**恒为白色**。
  也就是说它根本不读应用的配色，只读系统主题，而系统主题不跟随应用。
- 原生标题栏字体由系统绘制，**`--font-ui` 对它无效**。用户要求「这一块字体和全局一致」，
  在保留原生标题栏的前提下**物理上做不到**。

结论：`FormBorderStyle = None` + HTML 自绘标题栏。代价是要自己回填窗口能力，见下节。

### 2. 无边框窗口要回填的五件事（少一件用户立刻能感觉到）

| 能力 | 做法 | 坑 |
|---|---|---|
| 拖动 | `ReleaseCapture()` + `SendMessage(WM_NCLBUTTONDOWN, HTCAPTION, 0)` | 交给系统，别用 JS 算位移，否则掉帧 |
| 最大化 | `MaximizedBounds = Screen.WorkingArea` | 不设会盖住任务栏 |
| 缩放 | 页面边缘热区 → `winresize2 {dir,dx,dy}` → C# 套 `Bounds` | **没有 `WS_THICKFRAME` 时发 `WM_NCLBUTTONDOWN + HTSE` 系统不认**（实测 delta=0）；`screenX` 在 WebView2 里不跟随，必须用 `movementX × devicePixelRatio` 累加 |
| 最小化 / 关闭 | `winmin` / `winclose` 消息 | 关闭前必须先停投屏采集 |

> 这里踩了两次：第一版用 `WM_NCLBUTTONDOWN + HTSE` 完全无效；第二版改用 `screenX` 差值，
> DOM 侧看着对，但窗口纹丝不动。**判定依据只能是真窗口的 `GetWindowRect` 变化量**，
> 不能信 JS 里算出来的数。`_smoke_win.py` 就是干这个的。

### 3. 标题栏颜色与字体都走令牌，不写第二套

`--chrome` 负责底色，`--font-ui` 负责字体，两者跟顶栏、页面、弹窗完全同源。
所以「切主题标题栏不变」「切字体标题栏不变」这两类 bug 在结构上被消灭，
不需要额外写同步逻辑。验收方式也一样朴素：headless 渲染三套主题，
读标题栏那一行像素 —— dark `(22,21,24)` / light `(254,254,255)` / eye `(255,251,240)`，三者必须不同。

### 4. 设置抽屉：入口收敛，而不是功能删减

顶栏原来并排放着主题按钮、强调色按钮、品牌按钮，越加越挤。这轮把**所有**外观相关开关
（主题 / 9 色 / 字体 / 关闭）收进一个抽屉，顶栏只留「?」和齿轮。

要注意的两点：

- 收进去不等于降级：面板里的控件**本身也要跟随**用户选的字体与强调色，
  否则会出现「设置面板还是老字体」的割裂感 —— 这是很容易漏的一处。
- 删掉的 DOM 元素（`theme-btn` / `accent-btn` / `accent-pick`）要在不变量门禁里
  **逐条登记删除理由**，而不是把断言改松。门禁的价值在于「改动必须被解释」，不在于「永远是绿的」。

### 5. 全局字体切换的边界

内置 Inter 与 JetBrains Mono（均为 OFL，可随包分发，base64 内嵌 woff2，共 265KB）。
切换方式是改 `:root` 的 `--font-ui` / `--font-mono`，**不做任何按元素覆盖**。

三条边界：

1. **日志与代码区必须等宽**：即使正文字体选了楷体，输出区仍旧等宽，否则时间戳会错位。
   所以等宽是**独立令牌**，不是正文令牌的派生。
2. **改之前先清硬编码**：这轮把 34 处 `font-family: Consolas / "Microsoft YaHei UI"` 全部
   换成令牌。只要还剩一处硬编码，「全局切换」就是假的。
3. **自定义字体失败要可恢复**：本机没装的字体回退系统默认 + toast 提示，不能白屏或静默。

### 6. 文本页：编码与换行必须原样还回去

记事本的可用性事故几乎都来自两件事：把 GBK 存成 UTF-8、把 LF 存成 CRLF。
所以读写规则定死：**打开时识别编码与换行，保存时写回同一套**。

另外两个约束：单文件 2MB 上限（超了会卡界面，提示走外部编辑器）；
「未命名且未脏且为空」的标签要被复用，否则每开一个文件就多留一个空白页签。

## A13 轮设计说明（2026-11-15：四圆点 · 圆角双轨 · 跨屏最大化 · 终端多行）

### 1. 「不显示文字」的前提是有更快的文字

把 root / 无线 / 日志 / 设备 缩成四个圆点，等于把**语义从常驻改成按需**。
按需就必须快 —— 原生 `title` 有约 1 秒延迟，四个没有文字的圆点谁也不会等那一秒。
所以这一轮的真正成本不在圆点，在 `.tb-tip`：自建浮层 + 60ms 防抖 + 屏幕内夹紧。
**结论：砍文字之前先确认有没有「更快的补充说明」，否则就是把可读性换成好看。**

### 2. 圆角一次做不对，是因为三个平台能力要分开谈

| 系统 | 手段 | 结果 |
|---|---|---|
| Win11（build ≥ 22000） | `DwmSetWindowAttribute(hwnd, 33, DWMWCP_ROUND)` | 系统画，边缘抗锯齿，和资源管理器一致 |
| Win10 | `SetWindowRgn(hwnd, CreateRoundRectRgn(...))` | 裁剪区画，**边缘必然 1px 台阶** |
| 想要两层都不做 | 分层窗口 + 透明 | 不可行：WebView2 不支持 `WS_EX_LAYERED` 透明合成 |

三条硬约束：
1. `SetWindowRgn` **接管 region 所有权**，画完不能再 `DeleteObject`，否则偶发崩溃。
2. 裁剪矩形要 `Width+1 / Height+1`，否则右边和下边各留 1px 缝。
3. 最大化必须传 `IntPtr.Zero` 取消裁剪，不然最大化后四角是「圆的白洞」。

还有两个连带副作用必须一起处理，否则圆角会造出新 bug：
- **角部热区**：四角被裁掉一块，原来 5px 的缩放热区在角上几乎点不到 → 放大到 12px。
- **窗体底色**：`BackColor` 必须跟随主题，否则浅色主题下四角露出深色方块（比没圆角更难看）。

### 3. `MaximizedBounds` 是个陷阱

`MaximizedBounds = Screen.PrimaryScreen.WorkingArea` 只在 `OnLoad` 生效一次，
窗口之后被拖到另一块屏，这个值不会更新 —— 这就是「笔记本接 27 寸屏后最大化铺不满」。
正确做法是拦 `WM_GETMINMAXINFO`，**每次**按 `Screen.FromHandle(Handle).WorkingArea` 回答。
`MaximizedBounds` 留着无害（同屏时结论一致），但不能再当成主机制。

### 4. 多行命令不能用 `;` 拼

第一反应是 `a; b; c` 一次发下去，实际不可行：`cmds.ini` 里的命令是
`:car`、`stweakxxx` 这类**应用内前缀**，不是 shell 语法，拼起来会被当成一条乱命令。
只能排队：前端保存 `lines[]`，发第一条，等 C# 回 `end` 再发下一条。
停止按钮要把整条队列置空，否则「停了一条、后面继续跑」。
同样的队列早就在自定义指令里用过，这轮复用到终端。

### 5. 点空白展开/收起，必须先排除可交互元素

给表头挂 `onclick` 之后，点「导出」按钮也会冒泡到表头 → 一按就收起，功能像坏了。
所以 `fbHeadToggle()` 第一件事是 `closest('button,.fbtn,.fb-acts,input,select,a,textarea')`，
命中就直接 return。**凡是「点整块区域做事」的需求，第一步都是列白名单外的元素。**

## A14 轮设计说明（2026-11-15：网联服务 · 浅色对比度 · 自绘下拉 · 字体大小）

### 1. 「导出到桌面 logcat」不是一句话，是三条规则

同一个落点被三条命令复用（支付宝 / 微信小程序 / 车载微信），规则必须一致，
否则用户会在桌面看到三种目录结构：

1. **日期层**：`桌面\logcat\<yyyy-MM-dd>`（本地时间，与截图/录屏同源）。
2. **分类层**：`alipay` / `wmpf` / `wxmsg`。分类名走 `OutDir(kind)`，未知分类原样当目录名。
3. **活动日志先打包**：`Export(..., forceZip:true)` 在设备端 `tar` 成快照再拉。
   不打包就会出现"拉到一半文件被轮转删掉"——ANR/dropbox 就是这么踩过的。

### 2. 两个"同一个目录"的路径，要用主备而不是并列

微信小程序给了 `/sdcard/...` 和 `/storage/emulated/0/...` 两个路径，其实是同一块存储
（`/sdcard` 是软链）。两个都拉 = 传两遍，日志大的时候是几百 MB 的白等。
所以按**主 + 备**：先 A，失败才 B；同时两个落点名分开（`xlog_sdcard` / `xlog_storage`），
万一历史版本留下过另一个也不会互相覆盖。
**判断依据：用户给多条路径时，先问"是不是同一份数据"，是就做回退，不是才都做。**

### 3. 「重启后继续」这件事，只能写在代码里

用户的原话是"重启成功后检查设备上线则执行下面的命令，最多等 60s"。
`cmds.ini` 的一条 `run` 只能是一行命令，表达不了"等待 + 条件继续"，所以做成内置 `:sxlog`。
两个细节：

- 上线判定不能只看 `get-state`：刚回来时 `settings` 还没就绪，写进去会被吞。
  所以再确认一次 `sys.boot_completed=1`。
- 60 秒的 `sleep` 轮询必须可中断。GUI 的「停止」是 kill adb 进程，对纯 sleep 没用 ——
  所以加了 `App.GUISTOP`（StopWorker 置位、SubmitCommand 清零、循环每 2 秒读一次）。

### 4. 对比度是算出来的，不是"看着还行"

白天模式原来 `--border: rgba(60,60,67,.29)`，合成到白底约 `#d1d1d4`，
对比度 **1.7:1** —— 低于非文本 UI 元素 3:1 的建议值，所以"边框像没有"。
护眼更差：暖白底本身亮度高，`.28` 的暖棕边框只有 **1.4:1**。
这轮 light 提到 `.44`（2.2:1）、eye 提到 `.55`（2.05:1），并把结论写进 `_check_a14.py` 的断言里
—— 以后谁再调低，测试会红。

### 5. 原生 select 的弹层，CSS 治不了

`<option>` 的配色在 WebView2 里取决于浏览器进程，`color-scheme` 也不保证生效
（用户截图就是白底白字）。所以不跟它较劲：**捕获阶段拦 `mousedown`**，
自己画一层 `.a14-selpop`（主题令牌配色），选中后回写 `select.value` 再派发 `change`。
好处是既有 `onchange`（切换字体 / 编码 / 换行 / 投屏屏号）一行都不用改，
动态生成的 select（投屏 6 格）也自动覆盖 —— 因为拦的是事件，不是 DOM。

### 6. 字体大小用 ZoomFactor，不要逐条改字号

要让"整页跟随字体"，CSS 只有两条路：把所有 px 换成 em（几百处，必漏），
或者缩放根字号（对方 `px` 写的组件无效）。WebView2 的 `ZoomFactor` 是第三条：
浏览器级等比缩放 + 重新排版，一次到位。
两个前提确认过：`devicePixelRatio` 在 Chromium 里含页面缩放，所以窗口缩放热区的
物理像素换算仍然成立；固定定位的 tooltip 坐标也在同一坐标系里，不会错位。
