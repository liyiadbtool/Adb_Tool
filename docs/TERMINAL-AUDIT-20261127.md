## 一、USB 切换设备

| # | 严重度 | 问题 | 证据 |
|---|---|---|---|
| 1 | **高** | `DoDeviceSwitch` 只改 `SERIAL`，**不重置 `CUR` / `OLDPWD` / `PEND_K`** → 提示符停在旧设备路径，后续所有命令在失效目录里跑 | `GuiWeb.cs:5707-5726` |
| 2 | 中 | 切换后不清理命令历史与草稿（`hist` 是全局的）→ 上键会翻出旧设备的命令 | `ui.html:7210` |
| 3 | 中 | 切换后不重置诊断缓存（`_diag.car` / `_diag.skew` / 30s 新鲜度） | `ui.html:9400` 附近 |
| 4 | 低 | 切换会写回 ini `serial`，下次启动锁定该设备；插另一台时"连不上"的观感 | `GuiWeb.cs:5713` |

> #1 就是今天"车机信息整体错位 + cd .. 失败 + ls 报断连"的源头。

## 建议修复顺序

```
第 1 批（影响正确性）
  ① 切换设备/设备上线时校验 CUR，失效回落 /，并清 PEND_*/OLDPWD（#1 #9 #10 #11）
  ② 停止链路：长驻命令登记槽位进程 + 停 PERSIST_RUNNING + 补 pkill（#15 #18）
  ③ 停止后立即 PushEnd，UI 立即有反馈（#15 衍生）

第 2 批（对齐 cmd 习惯）
  ④ Ctrl+C 中断（复用停止链路）
  ⑤ 多行粘贴改为"回显不执行"，回车只跑光标所在行为默认（#23）
  ⑥ Ctrl+L / Ctrl+U / Ctrl+W（#22）

第 3 批（多设备/脏数据）
  ⑦ CUR/SERIAL 改为按槽位（#5 #6）
  ⑧ 切换设备清历史浏览位置与草稿（#12）
  ⑨ diag 缓存随设备失效（#3）

第 4 批（兼容性）
  ⑩ 输出编码自适应（#26）；Tab 补全（#21）
```

## 一句话结论

终端"能用"，但**状态管理是单设备的假设**：CUR / SERIAL / 历史 / 重试点都只有一份，
所以一旦换设备或多设备并行，就会出现"路径失效 → 命令静默失败 / 数据错位"这类连锁问题。
#1 和 #15 是最值得先修的两条。
