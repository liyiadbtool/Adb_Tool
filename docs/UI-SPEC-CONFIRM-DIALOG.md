# 确认弹窗统一规格（删除向添加看齐）

记录日期：2026-11-26　状态：**仅记录需求，未改代码**

---

## 1. 现象

H5 页两个动作的弹窗长得完全不同：

| 动作 | 实现 | 外观 |
|---|---|---|
| **添加条目/分组** | 页内自定义弹层（`h5-seg-add`） | 深色圆角、内嵌输入框、按钮在右侧、与整站主题一致 |
| **删除分组** | 原生 `confirm()` | 系统弹窗：标题是页面名「此页面显示」、按钮是系统样式、无法主题化、阻塞式 |

用户描述：**删除弹窗要向添加弹窗看齐**。

## 2. 根因

删除走的是浏览器原生对话框：

```js
// h5DelGroup
if (!confirm(msg)) return;

// h5DelItem
if (!confirm('删除「' + it.name + '」？\n\n此操作不能撤销。')) return;
```

原生 `confirm()` 的限制：

```
· 无法自定义样式（深色主题下白底/系统色，割裂）
· 标题固定为页面 title（截图里的「此页面显示」就是 H5 页标题）
· 同步阻塞，动画/过渡全部停止
· 按钮文案不可改（确定/取消 由系统语言决定）
· 无法显示"要删的内容摘要"以外的结构（列表、复选框）
```

## 3. 目标形态（与添加弹窗一致）

```
┌──────────────────────────────────────┐
│ 删除分组                        [×]  │  ← 标题与关闭
├──────────────────────────────────────┤
│ 确定删除「12345」？                  │
│ 该分组内有 3 条 H5，会一并删除。      │  ← 影响说明
│                                      │
│ ⚠ 此操作不可撤销                     │  ← 危险提示（红色小字）
├──────────────────────────────────────┤
│                    [取消]  [删除]    │  ← 危险按钮用 danger 色
└──────────────────────────────────────┘
```

要点：

| 项 | 规格 |
|---|---|
| 容器 | 与 `h5-seg-add` 同一套样式变量（surface / rim / r-4 / shadow-lg） |
| 标题 | 明确动作（删除分组 / 删除 H5 / 关闭应用…），不再用页面名 |
| 正文 | 对象名 + 影响范围 + 不可撤销提示 |
| 按钮 | 左侧次要「取消」，右侧主要动作；删除类用 danger 色 |
| 遮罩 | 半透明遮罩，点遮罩 = 取消 |
| 键盘 | Esc 取消，Enter 确认（焦点默认在「取消」上，防误按） |
| 焦点 | 打开时焦点进入弹层，关闭后回到触发按钮 |
| 动画 | 与现有弹层一致（fade + 轻微上移），不阻塞主线程 |

## 4. 影响面：全站 6 处原生 confirm 都应统一

| 行号 | 场景 | 现有文案 |
|---|---|---|
| 12915 | H5 删除分组 | 删除分组「xx」？里面的 n 条也会一起删掉。此操作不能撤销。 |
| 13000 | H5 删除单条 | 删除「xx」？此操作不能撤销。 |
| 18108 | UI 比对尺寸不一致 | 两张图尺寸不一致：… |
| 18393 | 自定义指令删除 | 删除「xx」？此操作不能撤销。 |
| 18532 | 关闭应用（文本有未保存） | 文本页还有未保存的文件，确定要关闭应用吗？ |
| 19173 | 关闭文本标签（未保存） | 「xx」还有未保存的修改，仍然关闭吗？ |

后 4 处虽然不是 H5，但同样存在样式割裂；统一成一个 `confirmBox(opts)` 后，
一次实现、全站复用（符合 R1 复用优先、R2 单一出口）。

## 5. 建议接口（一次实现，6 处替换）

```js
confirmBox({
  title: '删除分组',
  text:  '确定删除「12345」？',
  sub:   '该分组内有 3 条 H5，会一并删除。',
  danger: '此操作不可撤销',
  okText: '删除',
  okDanger: true,          // 按钮用红色
  onOk: function(){ ... }
});
```

实现要点：

```
· 弹层 DOM 挂到 <body> 末尾（避免 D3 那类 overflow/perspective 裁剪）
· 同一时刻只允许一个确认框（重复调用先关旧的）
· Esc / 遮罩 / 取消 三种取消路径返回同一结果
```

## 6. 优先级

**中高**：不影响功能，但删除是不可逆动作，弹窗样式割裂会降低“慎重感”，
且原生 confirm 在深色主题下白底闪一下很难看。

## 7. 验收标准

```
① H5 删除分组：弹窗样式与「添加」完全一致（圆角/深色/按钮位置）
② 标题显示「删除分组」，不再是「此页面显示」
③ 正文包含对象名 + 条数 + 不可撤销提示
④ Esc / 点遮罩 / 取消 均能关闭且不删除
⑤ Enter 或点「删除」才执行
⑥ 其余 5 处 confirm 全部替换，无系统白底弹窗残留
```
