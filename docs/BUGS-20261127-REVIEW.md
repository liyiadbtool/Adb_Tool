## B1【高】诊断报告丢了「界面隐藏项」(.NET 版本 / 进程数)

**现象**：诊断页「复制全部」和新增的「导出文件」，输出内容里都没有 `.NET 版本` 与 `进程数`。

**原因链**：

1. 早前按需求把这两项从界面隐藏，但要求"移到复制报告里"——当时我写了一份 `diagCopyAll`，内含：

   ```js
   if (r.k === '.NET 版本' || r.k === '进程数') extra.push(...)
   parts.push('【界面隐藏项】\n' + extra.join('\n'));
   ```

2. 该函数与既有 `diagCopyAll`（读 `#diag-fmt`，支持 text/md/json）**同名**，被后者覆盖，实际生效的是后者。
3. 本次"删除重复 diagCopyAll"时删掉的是我那份（含隐藏项逻辑），保留下的是三格式那份（**不含**隐藏项）。

**验证**：`grep -c "界面隐藏项" ui.html` → **0**。

**影响**：用户按需求"两项移入报告"的诉求失效；导出的 txt/md/json 都缺这两项。

**建议修法**：在三格式那份里补一段（md 用列表、json 用独立键、text 用两行），复用 `_diag.local`。

## B2【中】打开设备面板不再自动回填 IP、不聚焦输入框

**现象**：点设备胶囊 → 面板里的无线输入框是空的，光标也不在里面。

**原因**：回填与聚焦逻辑仍留在 `toggleWadb()`：

```js
// ui.html:18146-18151
var h = document.getElementById('wadb-host');
if (h) { if(!h.value) h.value = loadWadbHost(); h.focus(); h.select(); }
```

但 `.wadb` 已 `display:none`，`toggleWadb` 再也点不到；`openDevPop()` 里没有做这件事。

**影响**：每次无线连接都要手输完整 `IP:端口`（哪怕上次连过）。

**建议修法**：在 `openDevPop()` 的 `attachPop` 之后补回填（不强制 focus，避免抢输入焦点；或仅在面板内没有其它焦点时 focus）。

## B3【中】无线输入框里按 Esc，面板不关

**现象**：在设备面板的无线输入框内按 Esc，界面没有反应。

**原因**：`onWadbKey` 的 Escape 走 `closeWadb()`，而 `#wadb-pop` 现在是**空壳**（子节点已搬进面板），隐藏空壳对用户不可见。

**影响**：用户以为 Esc 失灵，只能点面板外关闭。

**建议修法**：`onWadbKey` 的 Escape 改为"关当前面板"（复用 V15 的关闭出口，而非 `closeWadb`）。

---

## B4【中】设备胶囊的 wifi 弧状态可能不亮

**现象**：无线已连接（尤其启动时就是无线连接）时，胶囊上的 wifi 弧可能不显示。

**原因**：`syncWadbArc()` 只在 `onWadb` 的回调里被调用（成功/失败两处）；没有首屏同步，也没有跟随 `wadb` 状态推送。

**影响**：状态指示不可信——用户看不出当前是不是无线连接。

**建议修法**：在 `setStatus()` 或 `wadb` 消息处理里也调 `syncWadbArc()`；首次渲染后补一次。

## B5【低】三条函数已成"空壳路径"

`toggleWadb` / `closeWadb` / `positionWadbPop` 仍作用于 `#wadb-pop`（已无子节点、`display:none`）。

不产生可见问题，但：

```
· 后续维护者会以为无线入口还在那儿
· _test_wadb_ui.py 里"断言 #wadb-pop display=flex"的用例已失去真实意义
  （它测的是空壳，不代表用户能用）
```

**建议**：加注释标明"入口已并入设备面板，此处仅保留契约"；测试用例改为断言"设备面板内存在 #wadb-host"。

## B6【待视觉确认】设备面板新增无线区块后可能溢出

`openDevPop()` 里 `renderDevRows()` 之后只 `placePop()` 了一次；面板顶部新增了"无线调试"区块（输入框 + 三个按钮 + 分隔线），高度增加约 90px。

**风险**：在小窗口（820×560）或设备列表很长时，面板底部可能超出视口。

**确认方法**：连多设备 → 打开面板 → 看底部是否被裁；可临时把 `placePop` 前后打印 `p.getBoundingClientRect().bottom` 与 `innerHeight` 比较。
