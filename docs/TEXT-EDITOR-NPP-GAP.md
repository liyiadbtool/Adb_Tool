# 文本阅读 vs Notepad++ —— 差距与改法参考

调研日期：2026-11-26　状态：**仅调研记录，未改代码**
参考来源：Notepad++ 官方仓库（基于 Scintilla 5.6 / Lexilla 5.5）与公开特性说明。

## 一、我们现在的实现（文件 → 文本阅读）

| 能力 | 现状 |
|---|---|
| 打开 | `OpenFileDialog`，上限 **2 MB**，超出截断并标记 |
| 编码识别 | 自动：UTF-8 BOM → UTF-16 LE（FF FE）→ 严格 UTF-8 → GBK(936) → ANSI |
| 编码切换 | 下拉四选一：UTF-8 / UTF-8 BOM / GBK / UTF-16 LE（`txSetEnc`） |
| 换行符 | 下拉 CRLF / LF（`txSetEol`） |
| 查找替换 | 有面板（Ctrl+F / Ctrl+H），支持「替换」「全部替换」，**无正则、无全词、大小写选项仅 1 处** |
| 编辑 | textarea + 撤销（浏览器原生） |
| 多文件 | 有标签（`tx-tabs`） |
| 视图 | 自动换行、字号缩放 |
| 保存 | `保存` / `另存为`，按 enc/eol 还原字节 |

## 二、Notepad++ 的关键逻辑（值得照搬的部分）

### 1. 编码：**「使用」与「转为」是两件事**（最重要）

| 操作 | 语义 | 是否改文件字节 |
|---|---|---|
| 使用 XX 编码重新打开 | **只改解码方式**，用于“猜错编码导致乱码” | 否 |
| 转为 XX 编码 | 按当前编码解码 → 按目标编码重新写入 | **是** |

Notepad++ 把这两个动作放在不同分组，并在状态栏显示当前编码（`ANSI` / `UTF-8` / `UTF-8-BOM` / `UTF-16 LE`）。

**我们的现状只有「切换编码 + 保存」一种语义**，用户分不清“看错了”和“要改文件”，
一旦选错编码再保存，原始字节就被写坏，且不可逆。

### 2. 换行符：显示 + 一键转换

- 状态栏显示 `CRLF` / `LF` / `CR`，点击即可切换
- 「显示所有符号」可看到 `→`（Tab）、`·`（空格）、`¶`（行尾）
- 保留“文件原本是 CRLF，我改成 LF 但没保存”这种**未保存状态**

### 3. 大文件策略

- 不把整个文件读进内存；按块加载、只渲染可视区
- 超大文件自动进入**只读模式**（禁用语法高亮/自动换行）
- 明确提示“文件过大，已只读”

我们的做法是 `TEXT_MAX = 2MB` 直接截断，提示语是“再大就不该用这个编辑器”——
对日志场景（经常几十 MB）不友好。

### 4. 外部修改检测

文件被别的程序改写时，Notepad++ 会提示「文件已被修改，是否重新加载」，
并提供「保留我的修改 / 重新加载」两个选择。

我们**完全没有**：编辑期间文件被日志进程追写，保存时会直接覆盖。

### 5. 查找替换

| 选项 | Notepad++ | 我们 |
|---|---|---|
| 匹配大小写 | ✅ | 🟡 部分 |
| 全词匹配 | ✅ | ❌ |
| 正则表达式 | ✅ | ❌ |
| 循环查找 | ✅ | ❌ |
| 跨所有打开文件替换 | ✅ | ❌ |
| 替换计数反馈 | ✅（“替换 12 处”） | ❌ |

日志排查里「正则 + 全词」是高频需求（如 `grep` 等价操作）。

### 6. 状态栏信息

`行:列`、选中字符数、文档长度、编码、EOL、`INS/OVR`。

我们只有编码/EOL 两个下拉，**没有行列定位**——排查日志要按行号找位置时很麻烦。

### 7. 会话与恢复

- 退出时保存打开的文件列表，下次恢复
- 定期备份 + 崩溃恢复（`备份 → 会话快照`）

我们多标签是内存态，重启即丢。

## 三、差距分级（按对“日志排查”场景的价值）

| 级别 | 项 | 为什么重要 |
|---|---|---|
| **P0** | 区分「使用编码重新打开」与「转为编码保存」 | 现在选错编码 + 保存 = 文件被写坏，不可逆 |
| **P0** | 外部修改检测（重载/保留） | 日志文件被持续追写，直接保存会丢数据 |
| **P1** | 正则查找 + 全词 + 大小写 | 日志排查的核心手段 |
| **P1** | 状态栏行列/长度 | 按行号定位是排查刚需 |
| **P1** | EOL 状态显示与未保存标记 | 现在改了 EOL 看不出“还没存” |
| **P2** | 大文件只读模式（替代 2MB 截断） | 几十 MB 日志目前打不开 |
| **P2** | 会话恢复 | 便利性 |
| **P3** | 语法高亮、列编辑、宏 | 与“日志阅读”目标关系弱 |

## 四、建议的落地顺序（与 D4 合并处理）

```
第 1 步（修 D4 + 打通导入）
  · 回包改用 fileNavSwitch('text')，打开后自动切到文本阅读
  · 打开失败/超大时给出明确提示（不只用 toast）

第 2 步（P0 编码语义）
  · 菜单拆成两组：
      重新打开为：[UTF-8] [GBK] [UTF-16 LE] …
      转换为：    [UTF-8] [GBK] …
  · 标题栏/状态栏显示「已修改（未保存）」

第 3 步（P0 外部修改检测）
  · 打开时记录 文件大小 + 最后写入时间
  · 保存前比对，若变化 → 弹窗「文件已被外部修改」→ 重新加载 / 强制覆盖

第 4 步（P1 查找替换）
  · 增加 正则 / 全词 / 大小写 / 循环 四个开关
  · 替换后回显数量

第 5 步（P2 大文件）
  · 超过 2MB 不再截断，改为只读 + 分段加载
```

## 五、结论

Notepad++ 值得参考的不是“功能多”，而是**两个语义边界划得清**：

```
① 解码（我看错了） ≠ 转码（我要改文件）
② 文件改了吗（外部变化） ≠ 我改了吗（本地未保存）
```

我们当前这两组状态都混在一起，于是出现：

- 选错编码 → 保存 → 原始字节损坏
- 日志被追写 → 保存 → 覆盖掉别人的写入
- 打开大文件 → 截断 → 用户以为文件只有 2MB

这三条都不是“功能缺失”，是**状态不可见、动作不可逆**。
